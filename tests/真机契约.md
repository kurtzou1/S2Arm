# App ↔ 测试层契约（测试出包线维护，10-19 起草）

真机执行器 `tools/dev_run.sh`、记分板 `tools/score_cells.py`、每帧分配闸门 `tools/frame_gate.py` 只认本文件写的东西。
App 侧（原生层 / 服务接入 / 帧率能耗线）按此输出；要改先发测试出包线，两边同一个提交里改。

## 3. frames.tsv（制表符分隔，首行列名，每上屏一帧一行）
由帧率能耗线（渲染循环）统一写，含 GC 列：渲染器与服务层在同一个 NativeAOT 镜像里，直接调 GC.GetTotalAllocatedBytes / GC.CollectionCount，不经跨线导出（10-19 三线定）。
| 列 | 单位 | 说明 |
|---|---|---|
| `frame` | — | 上屏序号，从 1 起 |
| `wall_us` | 微秒 | 与上一帧上屏的间隔 |
| `alloc_b` | 字节 | 本帧托管分配（`GC.GetAllocatedBytesForCurrentThread` 不够，要全进程：`GC.GetTotalAllocatedBytes(false)` 差分） |
| `gc0` `gc1` `gc2` | 次 | `GC.CollectionCount(n)` 累计值 |
| `rb_us` | 微秒 | 本帧 CPU 等 GPU 读回的阻塞时长 |
| `gpuq_us` | 微秒 | 本帧编码线程等命令分配器环的时长（GPU 跟不上的反压，不是读回；追加列，旧包没有） |
| `gc_pause_us` | 微秒 | `GC.GetTotalPauseDuration()` 的帧间增量；首帧为 0，全进程已完成 GC 的累计暂停，不包含并发 GC 的后台工作。追加列，旧包没有 |
| `draw_n` `pass_n` `upload_n` `rw_kb` | 次 / 次 / 次 / KB | 可选（帧率能耗线）：本帧绘制数、渲染遍数、主目标外切遍上传数、附件读写量。Mac 健康表按这几列比，缺任一列健康表记「不可比」 |
| `shader_miss` | 次 | 可选：本帧离线库未命中、现翻的着色器数 |
| `alloc_gpu_b` | 字节 | 可选：**编码线程**（渲染器 C# 所在、上屏记帧的那条线程，S2A_ALLOC_TRACE 拆账里叫「渲染·编码」）本帧托管分配。不是 Ryujinx GPU 命令线程（拆账里叫「渲染」，跑 GPFIFO 分派 / 贴图池 / 宏）——那条线程的分配只在 alloc_b 总数里、没有单列（10-23 两条线据列名误判过；列名不改，免得旧数据对不上） |
| `disp_us` | 微秒 | 可选：画面真正上屏的间隔（有显示层时才有值）。记分板帧率格优先用它，没有退回 wall_us（Present 时刻记时，带约 ±2 ms 抖动） |

## 4. host.log 标记（一行一条，按字面匹配）
| 标记 | 含义 | 谁用 |
|---|---|---|
| `S2A 就绪` | 运行时（原生层 + C#）已起来 | 起局 60 秒没有 → 红 |
| `S2A 标记 MARK：帧 <N>` | 到达代表场景（路线或自动玩家打） | 窗口起点；能玩格 |
| `[电] 电量 <N>%，<充电中|已充满|未充电>` | App 自读电量（每分钟一行） | 拔电时电量闸 / 局中停局 |
| `[声] 稳态窗口：输出峰值 <X>` | MARK 起 60 秒声音输出峰值 | 能玩格「有声」 |
| `[画] 满屏判据 已开` | 渲染器带满屏自检（起局打一次） | 画面格：没有这行满屏记「未测」 |
| `【红】出图未满屏：…` | 渲染器满屏判据 | 画面格 |
| `出图原比例居中（16:9 原比例页…）` | 渲染器满屏判据 + 宽屏包装层（10-20 维护者：游戏自己画死 16:9、没有更宽内容可补的页面留黑边原比例） | 不是红：两侧都是黑带且包装层认定本帧整画布 16:9 图片是纯 CPU 供图（从没被 GPU 写过）才算；GPU 画出来却没扩到的 16:9 页照报「出图未满屏」 |
| `【红】未实现：<服务或系统调用>/<号>` | 边界铁律 2：未实现一律报红、不兜底 | 计入报红数；M0 判据「报红 0」 |
| `【红】…` 其他 | 任何自检失败 | 计入报红数 |
| `CRASH` | 崩溃 | 能玩格 |
| `自检：窗口 <整块|不完整|退路段>（…）｜可用内存 <N> MB…` | 起局自检（原生层；iOS 要整块 64 GB 窗口 + ≥ 6144 MB，缺「提高内存上限」打【红】自检不过） | 记分板读数列、健康表自检列 |
| `地址余量：…` | 起局地址布局余量（原生层） | 只记录 |

## 5. 每帧分配闸门（方案 5a 第 3 行、5b-2）
窗口 = MARK 之后的帧（没有 MARK 取全局）。任一条超即红（10-22 维护者改：要防的是玩的时候因为回收而卡顿；原「窗内 gen0 增量 0」看的是累计分配压没压线，测的是运气）：
- 窗口平均每帧 `alloc_b` > 2048（60 帧）/ 4096（30 帧）；
- GC 停顿（10-23 维护者改「整局最长」，不只窗口）：第 1 帧到收局单帧 `gc_pause_us`（本帧 GC 停顿合计）> 帧预算 25%（按游戏自己要的帧率：30 帧 8.3 ms / 60 帧 4.2 ms）即红；gen2 那一帧（`gc2` 比上一帧涨）在游玩中照判——帧号 > MARK，或前后 30 帧 `draw_n` 中位 ≥ 本局 MARK 后 `draw_n` 中位的 1/4；MARK 前且绘制低于该门槛（读盘 / 黑屏）的单列记录不判；gen0 / gen1 不论在哪都判；没有这一列的旧包记「停顿未测」、这一条不判；frames.tsv 首行（第 0 帧，wall_us = 0）是启动以来的累计，不进窗口；
- 读回阻塞：窗口内 `rb_us` 合计 > 窗口墙钟 1%，或单帧 `rb_us` > 1 帧预算（33.3 / 16.7 ms）。读回阈值是首版取值，帧率能耗线有实测后改本节。
`gc0` / `gc1` 增量只记录、不判。不在 MARK 时强制 GC（会改变被测系统）。
frames.tsv 缺 `alloc_b` / `gc0` / `gc1` / `rb_us` 任一列 → 闸门「未测」，不判绿。


首局格（tools/score_cells.py，10-24 维护者 改）：本意是「玩家第一次玩不为首遇付费」（出包不试跑 + 首遇零延迟）。判法：任一到 MARK 的局（不分冷热，维护者「不管凉机还是热机，过了就行」），
全程 >100 ms 的帧（`wall_us` 与 `gpu_us` 取大）里我方开销造成的（当帧宏耗时 ≥ 帧时 70%，或当帧有当场翻译 / 建管线 / 现翻着色器）= 0，且 `shader_miss` 合计 = 0（没有这一列 = 未测）、`pso_n` 合计 = 0、「【首遇】管线特化慢」行 = 0 → 绿；
游戏自己读盘的「游戏加载停顿」只进读数。看板同包任一局绿即绿、判了的局都红才红（score_cells.vote）。10-23 起的「冷局 + 同包热局成对、扣热局同位置」作废。

## 5b. 能耗读数与 A/B 噪声底（10-23）
- 读数 = MARK 采样窗口两端功率采样（`pwh.plist` → `pw1.plist`，IORegistry `PowerTelemetryData`）的 `AccumulatedSystemLoad` 差 ÷ `SystemLoadAccumulatorCount` 差 ÷ 1000，单位瓦（`tools/score_cells.py` `window_power`）。这是整机耗电，不管电来自电池还是充电器；充电中照判，读数旁标充电状态和热档位（`energy_state`，维护者 10-23「标清读数的当时状态就行」）。
- 不用 `AccumulatedSystemEnergyConsumed`：它在充电时把充电功率也算进去。实测塞尔达 botw_1023201424_2（充电中，BatteryPower +3540 mW）用它折算出 7.12 W；同一局系统负载口径 4.11 W，同日未充电局是 3.70–4.00 W。
- 同包 A/B 噪声底（`tools/ab.sh report` 末行；`score_cells.ab_power_noise`）：按款查 `tools/ab_noise.tsv`。每款取同包 A/A ≥ 3 局（非充电优先）的极差；B−A 差的绝对值超过噪声底才算有差别。表里没有的款记「无噪声底，功耗不判」，不套别款的数（10-23 维护者定，原生层线测）。现登记：塞尔达 0.30 W（非充电 3 局 4.00 / 3.70 / 3.91 W）、动森 0.10 W（非充电 3 局 2.98 / 2.95 / 3.05 W）。

## 6. Mac 入口（健康表用，原生层线维护）
`runtime/run_mac.sh <款> <局目录> <秒>`：在 Mac 上用本树构建跑该款一局，输入目录由环境 `S2A_IN` 给（产物根快照，只读），
局目录写 `host.log`、`frames.tsv`（同第 3、4 节；没给路线 = 通用自动玩家），到秒数自行收局退出，退出码 0 = 正常收局。
GPU 栅栏等待超 3 秒必须判红退出（本机 GPU 卡死会触发看门狗整机重启，10-19 坑记录）。

## 7. 机器说明
- Mac 健康表只在本机（macOS 26）跑：gate-host（macOS 27）内核在程序启动前就往 64 GB 窗口里随机放 2×12 GB GPU 保留段，要整块 64 GB 的八方2 在 gate-host 上起不了局（原生层线 10-19 实测）。
- 签名只带「提高内存上限」（docs/研究/免费账号.md）：整块 64 GB 窗口 + 6144 MB 内存上限；不带扩展虚拟寻址。
