# 原生层 ↔ C# 接口（原生层线，10-19 起草，v1）

本文定「原生层（`runtime/`，C + 汇编）」与「C# 侧（Ryujinx 服务 / 显卡逻辑，NativeAOT 编进同一进程）」之间的全部约定。头文件 `runtime/include/s2a_native.h` 是本文的机器可读版，两者不一致以头文件为准、同步改本文。

## 0. 一句话

游戏 ARM 代码原生执行；它发出的系统调用经改写后的「门」进原生层。**线程 / 同步 / 内存 / 计时类系统调用原生层就地处理，永不进 C#；其余系统调用（服务请求为主）经同一个汇编跳板直入 C# 的单一入口**。游戏地址 = 宿主地址，C# 拿到的游戏指针直接解引用，零复制。句柄表只有一张，在原生层。

## 1. 分层与调用方向

```
游戏代码 ──(改写后的 svc：bl 门)──► sw_gate（entry.S，存寄存器、切宿主栈）
                                     │
                                     ▼
                          gate_dispatch（C，按门返回点哈希查 svc 号）
                     ┌───────────────┴────────────────┐
             原生集合（§2.1）                     其余号
     线程 / 同步 / 内存 / 计时 / 调试           │
     （runtime/svc_*.c，就地处理）              ▼
                                     g_s2a_cs.svc(&ctx)   ← C# 单一入口（§3）
                                                │  UnmanagedCallersOnly，一次跨界约 2 ns
                                                ▼
                                  Ryujinx IPC 分发 → 服务 → 显卡 / 声音
                                                │
                                   需要内核对象时回调原生层 API（§4）
```

- 原生层 → C#：只有 §3 的函数指针表（C# 启动时一次性登记），热路径只有 `svc`。
- C# → 原生层：§4 的 C 导出函数（`s2a_*`），C# 用 `[LibraryImport]` / `delegate* unmanaged` 调。
- 中间不经任何 C 服务层：原生层不解析 IPC 消息、不认服务名。

## 2. 系统调用分流

### 2.1 原生集合（永不进 C#）

| 类 | 调用号 |
|---|---|
| 内存 | 0x01 SetHeapSize、0x02 SetMemoryPermission、0x03 SetMemoryAttribute、0x04 MapMemory、0x05 UnmapMemory、0x06 QueryMemory、0x13 MapSharedMemory、0x14 UnmapSharedMemory、0x15 CreateTransferMemory、0x2C MapPhysicalMemory、0x2D UnmapPhysicalMemory、0x2A FlushEntireDataCache、0x2B FlushDataCache |
| 线程 | 0x07 ExitProcess、0x08 CreateThread、0x09 StartThread、0x0A ExitThread、0x0B SleepThread、0x0C/0x0D 优先级、0x0E/0x0F 核掩码、0x10 GetCurrentProcessorNumber、0x25 GetThreadId、0x32 SetThreadActivity、0x33 GetThreadContext3、0x36 SynchronizePreemptionState |
| 同步 | 0x11 SignalEvent、0x12 ClearEvent、0x16 CloseHandle、0x17 ResetSignal、0x18 WaitSynchronization、0x19 CancelSynchronization、0x1A ArbitrateLock、0x1B ArbitrateUnlock、0x1C WaitProcessWideKeyAtomic、0x1D SignalProcessWideKey、0x34 WaitForAddress、0x35 SignalToAddress、0x45 CreateEvent |
| 信息 / 计时 / 调试 | 0x1E GetSystemTick、0x24 GetProcessId（只认 0xFFFF8001 / 0xFFFF8000）、0x26 Break、0x27 OutputDebugString、0x29 GetInfo（核 / 优先级掩码、程序号、SystemResourceSize 全取自 NPDM；ResourceLimit 回句柄 0 = 无上限对象） |

### 2.2 进 C# 的（单一入口 `svc`）

原生集合以外的**全部**调用号原样交给 C#。服务接入线首批要接：0x1F ConnectToNamedPort（SDK 连 `sm:`）、0x21 SendSyncRequest、0x22 SendSyncRequestWithUserBuffer、0x23 SendAsyncRequestWithUserBuffer；之后按报红名单补（0x40 CreateSession、0x43 ReplyAndReceive 等）。

### 2.3 报红（铁律 2）

- C# 返回 `S2A_SVC_UNHANDLED`、或 C# 尚未登记入口：原生层记【红】一行（调用号、x0–x3、门所在模块 + 偏移），按 Horizon 回 `0xF201`（kernel NotImplemented），**不回 0**；同一调用号首次必打、此后每 2^n 次打一次。
- 严格模式（`S2A_STRICT=1`，Mac 冒烟 / 门禁缺省开）：首次即打回溯并中止。
- 计数：原生层按调用号累计「报红次数」，退出时写一行 `【红】未实现系统调用：0xNN×次数 …`，健康表读这一行；M0 判据「报红 0」即此行为空。
- GetInfo 不认识的信息类型、原生集合内未做的子功能，同样报红回 `0xF001`（InvalidEnumValue）/ `0xF201`，不回成功。

## 3. C# 单一入口（原生层 → C#）

C# 在启动时调一次 `s2a_register_cs(const s2a_cs_api *api)`（§4.1）登记以下函数指针；原生层只经这张表调 C#。

```c
typedef struct s2a_svc_ctx {
    uint32_t num;          // 调用号
    uint32_t thread;       // 当前游戏线程句柄（真实句柄，不是 0xFFFF8000）
    uint64_t *regs;        // 门帧：x0..x30（可读可写，出参写回 x0..x7），布局同 entry.S sw_gate
    void    *tlr;          // 当前线程 ThreadLocalRegion（0x200 字节，IPC 消息缓冲在 +0）
    uint64_t obj;          // 0x21/0x22/0x23：会话句柄已由原生层解析成 C# 登记时给的 cookie（§4.2）；其余 0
    uint32_t obj_kind;     // obj 的种类（S2A_OBJ_SESSION 等），无为 0
    uint32_t _pad;
} s2a_svc_ctx;

typedef struct s2a_cs_api {
    uint32_t size;                                  // = sizeof(s2a_cs_api)，版本核对
    int  (*svc)(s2a_svc_ctx *ctx);                  // 返回 S2A_SVC_HANDLED / S2A_SVC_UNHANDLED；Result 写 regs[0]
    void (*handle_closed)(uint32_t kind, uint64_t cookie);   // 游戏 CloseHandle 关掉 C# 种类的句柄（会话、C# 建的共享内存等）
    void (*thread_exit)(uint32_t thread);           // 游戏线程退出（C# 清该线程的缓存，如 Ryujinx 的 KThread 影子）
    void (*shutdown)(const char *why);              // 进程退出前（ExitProcess / SIGTERM / iOS 终止），C# 停声音 / 显卡
} s2a_cs_api;
```

约定：
1. `svc` 在**发起调用的游戏线程上**同步执行（原生 pthread，已切到宿主栈，栈余量 ≥ 512 KB；游戏建的线程宿主栈 1 MB，主线程 8 MB）。需要等待（延迟应答）时就地阻塞在托管等待原语上（抢占模式，不拖回收）；不许另起线程交接再回来（每次多 1.6–2.9 µs，见零分配与跨界.md B 组）。
2. IPC 消息原地读写：`tlr`（或 0x22 的 x0 用户缓冲）就是游戏内存，C# 直接按指针解析、直接写应答，不复制。
3. 托管分配：`svc` 稳态路径每次 0 字节（方案 §3-4）。原生层不在 `svc` 前后做任何分配。
4. 不许用 `SuppressGCTransition` 标 `svc`：它可能阻塞。C# 调原生层 §4 的函数中，标了「可 SGT」的才许加 SGT。
5. 每条游戏线程第一次进 C# 有约 1 µs 登记开销，只一次。
6. 原生层保证：`svc` 返回后才恢复游戏寄存器；`regs` 在 `svc` 期间不被别的线程改。

## 4. 原生层导出给 C# 的函数（C# → 原生层）

### 4.1 登记与进程信息
```c
int      s2a_register_cs(const s2a_cs_api *api);      // 启动时一次；返回 0 成功
uint64_t s2a_program_id(void);                         // 来自 NPDM / ACI，非写死
const s2a_layout *s2a_layout_get(void);                // §5 的区域表（只读，起局后不变）
uint64_t s2a_main_base(void);                          // 主程序模块装载基址（未装载 = 0）：金手指 main 区（Cheats.cs）
uint64_t s2a_main_region_va(uint64_t off);             // 金手指 main 区偏移按 Horizon 模块排布（main → subsdk → sdk 首尾相接）换成真实地址；超出起局模块 = 0（Cheats.cs）
const char *s2a_main_build_id(void);                   // 主程序构建号（十六进制串，没有 = 空串）
void s2a_cheats_host_enable(void);                     // 宿主有金手指界面（ios/vpad_cheats.m）时装载期登记
const char *s2a_cheats_dir(void);                      // 金手指目录 <文档根>/cheats；宿主没登记 = 空串
uint64_t s2a_process_id(void);                         // 游戏进程 pid（GetProcessId 与 C# 两边同值）
```

### 4.2 句柄表（全进程唯一一张，在原生层）
Horizon 句柄格式：低 15 位下标、高位递增序号；伪句柄 0xFFFF8000 = 当前线程、0xFFFF8001 = 当前进程。
```c
enum { S2A_OBJ_NONE, S2A_OBJ_THREAD, S2A_OBJ_EVENT_R, S2A_OBJ_EVENT_W, S2A_OBJ_SESSION,
       S2A_OBJ_SHMEM, S2A_OBJ_TMEM, S2A_OBJ_PORT, S2A_OBJ_CS_OTHER };
uint32_t s2a_handle_new(uint32_t kind, uint64_t cookie);       // 给 C# 对象（会话 / 端口 / 其他）发句柄；表满返回 0 并报红
int      s2a_handle_get(uint32_t h, uint32_t *kind, uint64_t *cookie);   // 0 = 无此句柄；可 SGT
int      s2a_handle_close(uint32_t h);                          // C# 主动关（如 move 句柄转出后）；1 = 关掉了，0 = 无此句柄
```
- 会话：Ryujinx 给游戏一个会话（sm 返回服务、域转出子对象）时，C# 调 `s2a_handle_new(S2A_OBJ_SESSION, cookie)`，把句柄写进应答。之后游戏对该句柄的 0x21–0x23 由原生层解出 cookie 放进 `ctx->obj`。
- 游戏 CloseHandle 一个 C# 种类的句柄：原生层从表里删掉、调 `handle_closed(kind, cookie)`。
- 游戏随请求递来的复制 / 转移句柄（如传输内存、进程句柄）：C# 用 `s2a_handle_get` 查种类与内容；0xFFFF8001 回 `S2A_OBJ_PROCESS`、cookie = 进程号。原生种类的 cookie 是可直接用的对象号：事件 → 事件号（要跨请求持有先 `s2a_event_retain`，用完 `s2a_event_release`）、共享内存 → 宿主指针、传输内存 → 0（用 `s2a_tmem_get`）、线程 → 线程 id。

### 4.3 事件（游戏可等待的对象一律是原生事件）
WaitSynchronization 永不进 C#，所以 C# 交给游戏的可等待对象必须是原生事件：
```c
uint64_t s2a_event_create(uint32_t *h_read, uint32_t *h_write);  // 返回事件号（C# 存着用来触发）；h_write 可传 NULL（只发读端给游戏）
void     s2a_event_signal(uint64_t ev);   // 任意线程可调；不分配；不可 SGT（取锁）
void     s2a_event_clear(uint64_t ev);
void     s2a_event_release(uint64_t ev);  // C# 不再持有；两端句柄都关了才真正释放
uint32_t s2a_event_dup_read(uint64_t ev); // 再发一个读端句柄（复制句柄语义：每次应答给新的）
```
Ryujinx 侧做法（服务接入线定）：`KEvent` / `KReadableEvent` / `KWritableEvent` 包一层原生事件号，`HandleTable.GenerateHandle(readableEvent)` 走 `s2a_event_create`，`Signal / Clear` 转原生，进改动清单。

### 4.4 共享内存与传输内存（后备都是宿主内存）
```c
uint32_t s2a_shmem_create(uint64_t size, void **host);   // 原生层分配 16 KB 对齐的后备，*host = 宿主指针（恒定），返回句柄
uint32_t s2a_shmem_wrap(void *host, uint64_t size);      // C# 已有的宿主后备（如 Ryujinx KSharedMemory 的页）包成句柄，不拷贝、不接管释放；host 须 16 KB 对齐，否则报红回 0
int      s2a_tmem_get(uint32_t h, uint64_t *addr, uint64_t *size, uint32_t *perm);   // 游戏 CreateTransferMemory 的那段游戏内存（游戏地址 = 宿主地址，可直接读写）；可 SGT
```
- 游戏 MapSharedMemory 时原生层把后备 `vm_remap` 到游戏选的地址（同一批物理页），C# 一直写 `*host`，游戏读到同一份。
- 4 KB / 16 KB 页差：原生层**只接受 16 KB 对齐的游戏地址**，不对齐回 0xD401 让 SDK 换地址重试（两代 SDK 都把 0xD401 当可重试、最多 64 次，连败概率约 (3/4)^64 ≈ 1e-8）。所以宿主缓冲永不重定位，C# 可以缓存 `*host`。旧库「按页内偏移重定位 + 服务登记锁」的做法不搬。

### 4.5 游戏内存（零复制）
- 游戏地址就是宿主地址。Ryujinx 的 `IVirtualMemoryManager` 由服务接入线实现成恒等：`Read<T>(va) = *(T*)va`、`GetSpan(va, n) = new Span<byte>((void*)va, n)`、`GetHostAddress(va) = va`。
- 远端（v2.13，地址空间线 10-27）：`const void *s2a_far_desc_get(void)` 回 runtime/src/far.c `s2a_far_desc` 的地址（定值，任意线程可调）。布局 `{ uint64_t lo; _Atomic int64_t *dir; }`：dir 为空 = 远端没开；否则 va ∈ [lo, lo + 2^36) 时 `dir[(va - lo) >> 21]` = 该 2 MiB 块「影子 − 游戏」的差值，0 = 这块没映射。C# `GuestMemory` 每次访问读一次 dir：空或 va 不在远端 = 原样；在远端 = 加该块差值。一段跨块且两块差值不同时：读给副本（`TryReadUnsafe` 回 false），写分段，`GetWritableRegion` 给副本、Dispose 时分段写回，`GetHostRegions` 按块切段（宿主上首尾相接的并成一段），`GetRef` 跨块抛异常。跟踪事件与写跟踪钩子仍用游戏地址；写跟踪代写（`WriteUntrackedHook`）只收不碰远端的段，碰远端的直接写影子。
- 合法性：IPC 缓冲描述符给的地址只编 39 位；窗口顶 = 2^39，游戏地址天然在 39 位内，**不补高位**。要核对时用：
```c
int s2a_mem_query(uint64_t addr, s2a_meminfo *out);   // 同 QueryMemory 语义（base / size / state / perm）；恒回 0（返回值约定的例外，结果在出参）；可 SGT
```
- 写跟踪（显卡缓存与游戏内存的一致性）不归原生层：C# 写游戏内存走 Ryujinx 的跟踪接口（显卡线实现）。**原生层自己改了游戏内存或权限**（堆伸缩、Map/Unmap、MapPhysicalMemory、宽屏陷阱代写）时调登记的钩子：
```c
typedef struct s2a_track_hooks {
    void (*prot_changed)(uint64_t addr, uint64_t len);   // 区间可访问性变了（新映射 / 解除）
    void (*host_write)(uint64_t addr, uint64_t len);     // 原生层即将写这段游戏内存
    void (*backing_changed)(uint64_t addr, uint64_t len); // 背后的物理页整段换掉（零拷贝缓冲作废重建）
    int (*guest_protect)(uint64_t addr, uint64_t len, int prot); // SetMemoryPermission：先占页再 mprotect，与缺页自愈串行；0 / errno
} s2a_track_hooks;
void s2a_register_track_hooks(const s2a_track_hooks *h);   // 显卡线登记；未登记 = 空操作
// 苹果换页事务（glue.c 登记 track.c 的 s2a_track_backing_begin / end）：改表系统调用先 begin（等在途排空期结束、挡住新的）、再改保护 / 换页、最后 end（提交了就重算记账）
void s2a_register_track_backing(int (*begin)(uint64_t addr, uint64_t len, uint64_t source), void (*end)(uint64_t addr, uint64_t len, int mapped, int committed));
```

### 4.6 线程
```c
uint32_t s2a_thread_current(void);                 // 当前游戏线程句柄；宿主线程上返回 0；可 SGT
uint64_t s2a_thread_id(uint32_t h);                // 同 GetThreadId
```
C# 自己的线程（显卡翻译、声音渲染、服务后台）是普通宿主线程，不进原生句柄表，不能被游戏等待。

- 系统计数器 `uint64_t s2a_guest_tick(void)`（v2.8）：游戏读 cntpct / cntvct、调 GetSystemTick 拿到的同一个值（19.2 MHz，宿主单调钟换算）。C# 凡是要和游戏计数器比的基准（时间服务共享内存的稳态时钟）都读它，不用进程内 Stopwatch。

- 全线程现场 `int s2a_dump_threads(const char *why)`（v2.9）：每条宿主线程的名字 / 优先级 / QoS / 状态 / pc / lr / 帧指针回溯（游戏地址写「模块+偏移」，宿主写符号），写 host.log（行首「[现场]」）与 <文档目录>/threads.txt。崩溃时原生层自己调；渲染器卡死判定在 _exit 前调。

### 4.7 测试层
- 渲染器每上屏一帧调 `s2a_frame_presented()`（原生层累计帧数给自动玩家）；frames.tsv 由渲染器写（帧率能耗线）。
- 标称帧率 `void s2a_nominal_fps_set(int fps)`（v2.14）：出图实际跟的节拍（30 / 60），渲染器每次上屏 / 节拍变化时报——通用模式 graphics/loop/RenderLoop.cs `FrameInterval`（SurfaceFlinger 生效交换间隔，含 S2A_FPS 地板；不限按 60），直连 graphics/nvn/host_adapt.m `dm_guest_frame_tick`（NVN 按 `nvn_present_fps`：帧步进 hold / display 模式 / 这一帧退回游戏间隔；GL 按 eglSwapInterval；Vulkan 按目标帧率）。原生层经 `s2a_ap_nominal_fps()` 交自动玩家折算按 30 帧写的路线 / 录手柄帧数；变了打一行「标称帧率：N 帧/秒」。
- 自动玩家（tests/autoplay）由测试出包线链进宿主；原生层出 s2a_ap_frames / s2a_ap_shutdown / s2a_ap_log，「S2A 就绪」后弱引用 s2a_autoplay_on 启动（没给 S2A_ROUTE 就开）；s2a_ap_draws 归帧率能耗线、s2a_ap_audio_mark 归服务接入线。

### 4.8 宽屏点（画幅线定的机制，原生层实现）
- 出包：`patch_nso.py <NSO> <产物目录> <模块名> [widen_sites.tsv]`，第 4 参是画幅线扫描器 graphics/widen/scan/wide_scan.py 的候选表；不给时产物与原先逐字节相同。
  movz / asp / f2w 换成读键页值槽的跳板（跳板顺手写命中槽；LDR Wd 读值槽低 32 位，写 Wd 清 Xd 高 32 位），aspdiv / aspstr / lytsz / capsz 换成宿主门（种类 wide），f32 不动代码；输出 `<名>.widen.tsv`。
- 运行：装载时按 `S2A_SCREEN_W`（缺省 1920 = 全部原值；iOS 没给时 App 壳按横屏 1080 × 长边 ÷ 短边）与启用表填值槽、改 f32；
  启用表按档位 = 模块目录 `widen_enable.<handheld|docked>.tsv`（模块 / 偏移 / 种类 / 启用），按服务层同一开关 `S2A_DOCKED`（"1" 主机，其余掌机）读当前档位那张，没有 = 不加宽；只放该档位闭环全过的点集（10-21 起不再合并两档）。试验时 `S2A_WIDEN_SITES="main:0x4075720,…"` 整表覆盖。
  取值：movz 档宽 × 屏幕宽 ÷ 1920 取偶；asp → 屏幕宽 ÷ 1080（未启用 = 原 MOVZ 低半 | 0x3fe3 << 16，认 0x8e39 / 0x8e3b 两种）；f2w（MOVZ Xd,#hi16(宽.0f),LSL#16，后接 MOVK Xd,#hi16(高.0f),LSL#48）→ 值槽 = 加宽后宽度的完整浮点位（如 1564.0f = 0x44c38000），MOVK 原样执行；aspdiv / aspstr 结果与 16:9 差 < 2e-3 时换成屏幕宽 ÷ 1080；lytsz / capsz（LDP Sa,Sb,[Xn,#imm]，界面布局画布尺寸 / 拷屏控件尺寸，10-21 起；wsite 种类号 7 / 8）门里照读两个浮点，是 16:9 档宽高对时宽 → 档宽 × 屏幕宽 ÷ 1920、高不动；f32 1920.0 → 屏幕宽。未启用的点结果与原指令逐位相同。
- 屏幕宽：`int s2a_screen_w(void)` 是唯一来源（v2.5）——`S2A_SCREEN_W` 优先，iOS 没给时按实际屏幕算，越界按 1920；原生层宽屏点与 C# 宽屏包装层都调它，C# 不再自己读环境变量。
- 游戏自己出宽图：`int s2a_widen_game(void)`（v2.6）——屏幕宽 > 1920 且装载时启用的宽屏点 ≥ 1 回 1；C# 宽屏包装层据此只管界面层、不放宽贴图（取代画幅线提的 S2A_WIDEN_GAME 环境变量）。
- 游戏界面布局也是宽的：`int s2a_widen_layout(void)`（v2.12）——s2a_widen_game() 为 1 且装载时启用了界面布局尺寸点（lytsz）回 1；C# 宽屏包装层据此不再把读改写矩阵的界面层局部剪裁收进中间（游戏已按宽屏像素算剪裁）。
- 第三层整套放宽验过：`int s2a_widen_full(void)`（v2.11）——模块目录 `widen_full.<handheld|docked>.tsv` 有一行「1」回 1，否则 0；`S2A_WIDEN_FULL=1/0` 覆盖。屏宽 > 1920、第二层没生效且本函数回 0 时，C# 包装层不放宽，16:9 原比例居中留黑边（每帧告诉出图层是原比例页）。
- 命中：跳板点每秒扫一次命中槽、收局前补扫一次，门点进门即打，都打 `[宽] 点 <模块>+<偏移> 首次命中（<种类>）`。

## 5. 地址空间（方案 5a 定案落地）

- 进程最早时刻（`runtime/vawin.c` 的 `__attribute__((constructor(101)))`，早于 NativeAOT 运行时与 Metal）`mmap(0x70_0000_0000, 64 GB, PROT_NONE)`（不带 MAP_FIXED，核对落点）；落点不对或失败 → 打 vm 全表、红停。
- 没有退路（10-20 删）：整块占不到（gate-host macOS 27 实测内核在 dyld 阶段就往 [0x70, 0x80) 里放两段各 12 GB「GPU Carveout (reserved)」）就报红「地址窗口不足」、host_main 退出，不再 MAP_FIXED 覆盖内核保留段取部分窗口（覆盖内核保留区本身不对；gate-host 退路局 7 局崩 6）。产品在 iPhone 上整块必占得到；占不到的开发机不跑游戏局。布局只接受整块 64 GB、1 GB 对齐的窗口。
- **窗口与布局（10-27 地址空间根修，docs/方案_地址空间根修.md）**：Horizon 各区是地址承诺，不等于宿主占用。窗口按「标准布局跨度」（s2a_layout_need：系统资源为 0 的款 32 GB + 模块；非 0 的款 63 GB 别名区 + 栈 / 应用池堆 / 余量 + 模块）在 2^39（或系统给的地址上限）以下的空洞里要，不带 MAP_FIXED、核对落点；放得下 = 甲布局（各区全有宿主地址，iOS 27 / macOS 的 [0x70, 0x80)）；放不下 = 乙布局：取最大空洞、下方留 1 GiB 给宿主（起局核对别名区伸出段，压到宿主可访问映射即报红），模块 / 栈 / 堆 / 余量在窗口前段，别名区在其后伸出窗口（伸出段只是承诺，内容放远端影子区，游戏一碰即缺页代执行，far.c；iOS 17 / 18 / 26 带 increased-memory-limit 的大地址档即此情形）。addr_need.tsv 的「别名区GB」> 0（出包静态识别开局要巨大地址区）= 乙布局别名优先：堆区 64 MiB + 影子余量 128 MiB、别名区紧接前段不按 GiB 对齐。给不出前段就在自检页写「本款需要 N GB 地址空间，本机最多 M GB」。`S2A_WIN_NEED_MB` 只给单测 / 不带 NPDM 的工具用；`S2A_VA_IOS26=1` 只在 Mac 上模拟 iOS 26 大地址档。
- **iPhone 上 Metal 也要这个窗口**（测试设备1 实测 10-19，探针包 = 本仓 vawin.c + NativeAOT 建 256 MB 存活堆 + Metal 逐档共享缓冲，累计持有）：
  | 占窗方式 | 1 / 16 / 64 / 256 MB | 512 MB | 1 GB | 2 GB |
  |---|---|---|---|---|
  | 不占 | 成（落在 0x1_xxxx 低区空洞） | 成 0x7000000000 | 成 0x7020000000 | 成 0x7060000000 |
  | 整窗 64 GB | 成（低区） | **败** | **败** | **败** |
  | 底部 63 GB（八方2 布局） | 成（低区） | 成 0x7fc0000000 | 败 | 败 |
  | 底部 48 GB | 成（低区） | 成 0x7c00000000 | 成 | 成 |
  NativeAOT 建堆前后窗口都没被动过（三个时刻窗口完整）。结论：低区空洞只放得下 ≤256 MB 的缓冲（合计约 1.5 GB），≥512 MB 的共享缓冲只能进窗口。
  所以不用虚拟地址内存的游戏只占前 32 GB；**用虚拟地址内存、要 63 GB 别名区的游戏（八方2）在 iPhone 上留给 Metal 的只有窗口末 1 GB 以内 + 低区空洞**，渲染器的 CPU 可见大缓冲要按此设计（已报维护者与帧率能耗线）。
- 每次起局打三次窗口探测（构造函数、C# 运行时初始化后、Metal 设备建好后），读数一行 `窗口探测 t=… 空/占 …`，健康表读。
- 区域按 NPDM 的地址空间类型与 SystemResourceSize 在窗口内重排；SystemResourceSize 非零表示使用 VAMM，但不声明游戏未来的普通堆 / 别名区申请大小。VAMM 预算由构建参数 `IOS_VAMM_LAYOUT=alias|balanced` 选择，`make ios` 默认 `alias`：

| NPDM | 别名区（Alias） | 堆区 | 栈区 | TLS/IO 区 | 可随机区（GetInfo 12/13） |
|---|---|---|---|---|---|
| SystemResourceSize ≠ 0，alias | 窗口开头 2 MB 起约 63 GB，1 GB 对齐（八方2 下限 63 GB：元数据 0x3FE0_0000 + 1 GB 对齐 + 62 GB） | 32 MB | 128 MB | 约 2 MB（窗口开头） | 别名区之后 256 MB（含栈 / 堆，不含别名区）；窗口其后约 766 MB 起局时还给系统（10-21 缩尾部，原 1022 MB；依据当时正式局「游戏地址峰值」：栈区映射最多 33.8 MB、堆最多 6 MB、共享内存最多 260 KB，不覆盖惊奇的大普通堆申请） |
| SystemResourceSize ≠ 0，balanced | 窗口开头约 2 MB 至窗口 + 56 GB + 16 KB | 6 GB | 128 MB | 约 2 MB（窗口开头） | 窗口 + 56 GB + 2 MB 至窗口 + 63 GB（含栈 / 堆，不含别名区）；最后完整 1 GB 起局时还给系统 |
| SystemResourceSize = 0 | 8 GB | 6 GB（≥ 应用内存池 3285 MB） | 2 GB | 1 GB | 窗口前 32 GB；后 32 GB 起局时还给系统（Metal 大缓冲要用，见下） |

  具体偏移见 `s2a_layout`。惊奇 1.2.1（`smbw`）实际调用 `SetHeapSize(0x5b200000)`，超过 alias 的 32 MB 堆，因此 `pack/ipa.sh smbw` 默认选择 balanced；其他款仍默认 alias。可通过 `IOS_VAMM_LAYOUT=alias|balanced` 环境变量显式覆盖。balanced 放不下八方2固定的 62 GB 别名申请，不能作为所有 VAMM 游戏的默认。普通堆的应用池限制仍由 SVC 检查，不因虚拟预算增大而放宽。

  包键只在布局不是 alias 时加入 `vamm=<布局>`，alias 保持旧键逐字不变；惊奇缺省 balanced 必须与旧 alias 包区分。App 的 `Info.plist` 用 `S2AVammLayout` 记录所选参数。`make native-test-layout` 同时验证两种布局及非 VAMM 布局，真机画面和后续运行须另行验证。
- 模块映像（main / subsdk / sdk）放窗口外（宿主挑址），QueryMemory 按真机分段回报；旧库九款已证可行。
- 线程 TLR（0x200）在窗口 TLS/IO 区里按页分配，C# 拿到的 `tlr` 在窗口内。
- 4 KB 游戏页 vs 16 KB 宿主页：MapPhysicalMemory / Unmap 按 4 KB 子页掩码记账（旧库 hle_vamm.c 做法搬过来），整宿主页空了才还物理页。

### 5.1 窗口基址约定（10-24 定，鸿蒙 #4 / macOS 护栏同一类问题）
**约定：窗口基址由平台层定，其余代码一律读变量，不写死。**
- 平台层（`runtime/src/vawin.c` 苹果、`runtime/ohos/vawin_ohos.c` 鸿蒙、安卓同理）在起局前占好窗口，经 `s2a_window_get(&base, &size)` 交出；`s2a_layout_compute(…, base, size, …)` 按它重排各区域，系统调用层只读 `L.win_base / L.win_size`。
- 窗口必须满足三条，平台层自己保证，占不到就不起局：① = 本款所需跨度（`s2a_layout_need`；10-24 前写死整块 64 GB）；② 基址 1 GB 对齐（`layout.c` 已检查，不满足返回 -2）；③ 基址 + 64 GB ≤ 2^39。第 ③ 条是硬约束：客体地址就是宿主地址（不做转换），而 HIPC 缓冲描述符只编 39 位地址（Ryujinx 补丁 0015 里 `& 0x7000000000` 是描述符第 36–38 位的掩码，不是窗口基址），39 位地址空间的游戏也按 39 位处理指针。
- `S2A_WIN_BASE`（0x70_0000_0000）是**苹果专属**：iOS / macOS 进程里 2^39 以下只有这一块 64 GB 空洞（下面是 dyld 共享缓存与 GPU 保留区）。只给 `vawin.c`（占窗口）、`macos/vaguard.c`（Mac 护栏）、Mac 上复现 iPhone 地址约束的代码、`selfcheck.c`（只在 iOS 编）用；鸿蒙 / 安卓不引用它。
- 现有代码核过（10-24，git grep 全仓）：写死 0x70_0000_0000 的只有上面这些苹果专属处和工具 `graphics/metal/tools/vaprobe`；`layout.c`、`svc_mem.c`、别名映射、GAL 都按变量算，不用改。
- 低区预算是苹果特有约束：iPhone 上窗口外只剩约 2 GB 低区，而 .NET GC 段模式只能用这块（新段落到远处要扩卡表覆盖整个跨度，见坑记录 10-24）。鸿蒙窗口外空洞约 400 GB，健康表的「低区空洞」读数在鸿蒙上换成「窗口外可用空洞」口径，不当约束。窗口尾部统一分配（`s2a_tail_map`）在鸿蒙上可以不接管尾部，调用方照常走退回路径。
- 低区账（`runtime/src/lowva.c`）的峰值读数：收局与崩溃各打一行「宿主地址 [收局|崩溃]：起点空洞 T0、最低 Tmin（第几秒）、峰值占用 T0−Tmin、最大一块最低 Bmin（第几秒）；最低点按标签：…」。T0 − Tmin 就是这一局宿主（Metal 驱动与编译器、写跟踪、malloc、文件映射、C# 运行时）在窗口外最多多占了多少地址，即宿主地址预算的「需求」；与「窗口外剩多少」（供给，由系统布局决定）对比用。读数常开：设限的款每次扫描都记，不设限的款每 5 秒扫一次（只记峰值，不腾退、不报红），所以短于 5 秒的尖峰会漏记。按标签合计只在 T 比上次快照低 ≥ 64 MB 时重存。

### 5.2 外置镜像包（iOS，11-04 全外置；唯一路径）
- **形态**：iOS 主程序是与游戏无关的预编壳（`pack/shell_build.sh`，按提交出一次，主程序里没有任何游戏镜像）。全部游戏模块（main / sdk / subsdk* / nn::ro 装的 NRO）的改写映像写成包内 `Frameworks/S2AImages.dylib`：主程序不链接、dyld 不装。
- **文件**：`ios/embed.py`（纯 Python，`ios/macho_dylib.py` 写 Mach-O，不经 Apple 链接器，Windows / Mac 同输入逐字节相同）。三节：`__TEXT,__swcode`（全部代码块 x0 / x1 / x2，纯指令节）、`__SWDATA,__img`（全部可写块 W）、`__TEXT,__swidx`（偏移表：魔数 `S2AEMB01`、u32 项数、u32 项长 88；每项名字 24 字节 + 4 ×（u64 节内偏移, u64 长度），块序 x0 / W / x1 / x2）。每块 16K 对齐。文件自带预留签名区与链接器式 ad-hoc 签名（`LC_CODE_SIGNATURE` 在最后），codesign / zsign / rcodesign / 侧载工具都按「替换已有签名」原地重签。
- **运行时**（`runtime/src/imgpack.c`，`loader.c` iOS 分支）：进程内打开一次（fd 常开）→ 读头与偏移表、核魔数 / 16K 对齐 / 依次排开 → `fcntl(F_ADDFILESIGS_RETURN)` 注册签名 + `F_CHECK_LV` 库校验（要与主程序同团队重签；只有 ad-hoc 签名时注册被拒，11-04 测试设备2 探针）→ 按名 / 块号查 → `mmap(MAP_FIXED | MAP_PRIVATE)`：代码块 R|X 且最大权限压到 R|X，W 块 R|W 写时复制。包不在、打不开或签名不过：停。
- **只读偏移表**（`s2a_imgpack_index` / `s2a_imgpack_free`，11-07 多款容器）：只读 Mach-O 头、load commands 与偏移表，不注册签名、不进「同一路径回同一个包」的表、fd 读完即关，只能查块长不能映射。多款容器构造期按各款镜像包 `Frameworks/S2AImages-<游戏号>.dylib` 的 x1 块长算窗口需求用（`loader.c` `s2a_loader_span_images` ← `vawin.c` `s2a_window_container_need`），玩家没选的款不注册签名。
- **代码页语义**（11-03 测试设备2 实测）：映射后不能释放、不能覆盖（munmap 回 0 但留「权限 0 / 最大 0」占位，再映射 EACCES）。nn::ro 卸了再装、进程内重启都原地复用代码页、只重映 W（`remap_writable`、`code_same` → `s2a_imgpack_same`）；窗口复位留着代码页（`vawin.c`，判据 `s2a_prot_is_code`）。
- **为什么**：游戏代码不再随主程序被 dyld 映射进宿主唯一的低区（11-03 01006A800016E000 764 个 NRO 编进主程序吃掉低区约 1.7 GB、首局地址耗尽）；玩家机出包不需要 Xcode / SDK / 链接器（Windows 出 iOS 包的前提）。
- **组装**：`pack/ship_ext.py build`（壳 + 产物根 → 未签名 App：写镜像包、拷随行表 / main.npdm / 随包表；先核壳清单、要求壳编号与打包器同源）；`pack/ipa.sh` 固定走这条。

## 6. 启动顺序（宿主 `main()` 归原生层）

1. 构造函数：占窗口、探测 #1。
2. 读 NPDM → 算布局；装载模块（`runtime/loader.c`），登记门。
3. 初始化 C#：调 NativeAOT 导出的 `S2A_Init(void)`（服务接入线提供；§4 的函数 C# 直接按符号 P/Invoke，同一进程静态链接），C# 在里面调 `s2a_register_cs`。探测 #2。
4. 显卡线初始化 Metal（`S2A_GfxInit` 或由 C# 内部做），探测 #3。
5. 主线程切到游戏主线程栈，照 `nn::init::Start` 顺序进 SDK 初始化 → nnMain。
   宿主参数：只在起局方给了参数（`--` 之后）时调 SetHostArgc / SetHostArgv；没给就保留 SDK 缺省 `g_CommandLineParameter = {1, {""}}`（真机值）。
   坑（10-20）：曾无条件设 argc = 0，怪猎 nnMain 按「argc ≥ 1」写，argc = 0 走进真机走不到的分支，把 operator new 后残留的 x8 当 argv[0]，解析 runtime.args 时段错误——表象像 RomFS 读错，实为宿主参数。
- 没链 C# 时（原生层单测 / 冒烟）`S2A_Init` 是弱符号空实现，所有 §2.2 调用报红。

- 起局分段计时（v2.7）：每段打「[起局] <段> +<距进程创建 ms>（本段 ms）」，起点是内核创建进程的时刻（含 dyld）；原生层打 占窗口 / 进入 main / 自检 / 装载 / 内存布局 / S2A_Init 返回 / 游戏主线程 / SDK 初始化 / 全局构造 / 首帧上屏。C# 在 S2A_Init 里要分段就调 `s2a_boot_mark("<段名>")`。

- 确定性调试（缺省关，产品与验收局永远真并行；只锁游戏线程，宿主线程照常并行）：
  `S2A_DET=1` 串行：同一时刻只有一条游戏线程跑（游戏代码 + 系统调用），只在阻塞等待 / 睡眠 / 读计数器处交接；看门狗记超过 `S2A_DET_SLICE_MS` 不进门的次数与 pc。
  `S2A_DET_REC=<文件>` 记录 / `S2A_DET_PLAY=<文件>` 重放：一条全局追加日志（16 字节一项，持锁者写，天然有序）——交接轮次、计数器值、系统调用输出寄存器（IPC 带回包 0x100 字节）、阻塞结局（被唤醒 / 超时，在重新轮到自己那一刻定）、宿主线程对事件的触发 / 清除（宿主线程从不等串行锁：试拿不到就进待办队列，持锁者放锁前按序生效并记下；重放时宿主的真触发忽略，只按日志生效）。重放按日志强制同一轮次与结局，计数器回录的值，GetInfo / IPC 回包按录的覆盖，其余系统调用真执行后比，第一处不同打「重放分叉」。
  确定性档下：游戏线程持锁时分配的句柄与宿主异步分配的分用前 / 后半表、各自代数（否则句柄号每局不同）；C# 处理的系统调用返回后非输出寄存器恢复成调用前的值。
  宿主写游戏内存（v2.10）：`void s2a_det_host_write(uint64_t 地址, const void *源, uint64_t 长度)`——C# 往游戏内存的写都经它；确定性档关时就是 memcpy。记录档：持锁游戏线程（含它的 C# 处理）直接写；其余宿主线程拿不到串行锁就入待办（32 MB 字节环），持锁者放锁前按序写进去并记录内容；重放档只按日志写。
  共享内存（记录 / 重放档）：游戏一侧映射独立影子副本（权限照请求），宿主写后备；持锁者拿到轮次时（≤ 每毫秒一次）把后备与影子的差异发布进影子并记录，重放只按日志发布。
  射程：只为「同一局记录 → 重放」；只有真并行才出现的竞态（宿主线程之间的互锁、游戏线程真并发的数据竞争）复现不了，那类靠全线程现场（s2a_dump_threads）。宿主线程往游戏内存里写的数据（HID / 时间共享内存、IPC 输出缓冲、GPU 回写）还没进日志，是当前的分叉来源。
  10-20 实测（Mac 01006F8002326000带存档）：串行 150 秒交接 398 万次、强制让出 0 次，41.2 ms / 帧（并行约 33 ms）；关闭时每次门多 3 个打点约 4 ns（t_det）。
  记录 20 秒 → 重放：第一处分叉从第 1 项推到第 47510 项（补上放锁清待办后重量），加共享内存影子后推到第 60956 项（等待对象重放时未被触发）；服务层写游戏内存（GuestMemory）还没接 s2a_det_host_write，是下一个分叉来源。
  10-20 现状（维护者定：停在这里，留作工具）：服务层 GuestMemory 已接（103b1f4）；事件在第一次对游戏可见（持锁建 / 复制读端 / 游戏第一次等、清、重置）时编号并记当时状态；记录 / 重放档游戏线程 TLS 块与线程对象从 TLS/IO 区顶端按序分配。
  同口径分叉在第 211 万–514 万项（全长约 850 万，最好 60%、重放出 212 帧）；开机段（检查点每 200 次交接时跑不到首帧）598 万项全部对上。
  剩下的分叉形态：16 号线程重放时少睡一次（轮询某个标志），嫌疑是 GPU 直接写游戏内存（零拷贝缓冲上的信号量 / 查询结果，不经 C#）；另有堆开头约 1.7 KB 宿主堆地址每局不同（第 1000 次交接前写入，暂不影响走向）。
  诊断开关（都缺省关）：`S2A_DET_HASH_EVERY=<交接次数>` 游戏可写内存每 1 MB 一个哈希 + TLR，重放打第一块不同；`S2A_DET_DUMP=<检查点>:<块地址>` 两边落盘离线比字节；`S2A_DET_WATCH=<地址>`（`S2A_DET_WATCH_TURN` 第几次交接后才上）页只读、打第一次写的位置；起局打宿主映像加载偏移。分叉时打游戏线程表（含等待句柄）。

## 7. 线程与回收器

- 每个游戏线程 = 一个宿主 pthread，跑在游戏给的栈上；进宿主代码（门、C#）一律切到本线程宿主栈（hle_xstack 机制）。
- 游戏线程只在 `svc` 里处于 C#；其余时间回收器不等它、不停它。
- C# 回调原生层（§4）时，凡可能取锁的函数都是普通 P/Invoke，不得加 SGT；标「可 SGT」的只读查表函数不取锁、不分配。
