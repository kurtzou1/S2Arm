# 安卓 / 鸿蒙新图形层 · 联合开发

面向联合开发者（安卓组、鸿蒙组）。安卓与鸿蒙现在都**不对玩家发包**，README 仍是「coming soon」；这一页说的是怎么一起把新图形层做完。

设计与分层见 [设计_Vulkan回放层重搭.md](设计_Vulkan回放层重搭.md)。一句话：游戏的图形调用录成命令流，**回放核心**（`graphics/nvn/replay/`，纯 C，不含任何图形接口与平台头）把它变成对 **Vulkan 后端**（`android/native/nvn/backend_vulkan.c`，实现 `nvn_gpu_*` 契约）的调用，换操作系统要重写的东西只在**平台件**（安卓：`android/native/gfx_plat/`）。

帧率读数的口径：同一台手机连跑多局会发热限频（大核上限从 4.32 GHz 掉到 2.2 GHz 左右），跨局比帧率要同时记电池温度和 `scaling_max_freq`。新层每 5 秒打的「分时」几行（帧率、回放各步、通道构成、写跟踪）是比对的依据；调试开关 `debug.s2a.nvk_gputime` 另给每段的 GPU 时间。

## 现在能领的任务

### A. 设备普查（不写代码，最需要人）
拿自己的设备、自己的游戏，用新层起一局，把结果贴成 Issue（模板「安卓 / 鸿蒙新图形层 · 设备普查」）。骁龙 8 Elite 以外的任何芯片都是新读数：Mali、其它 Adreno、Xclipse、PowerVR、麒麟 / 鸿蒙设备。

步骤：按下面「怎么编出新层的包」装包 → 在应用里导入游戏 → 设备接电脑 → 跑：

```bash
bash android/tools/nvk_survey.sh <程序号> 60
```

脚本直连起一局、等 60 秒，在输出目录里写 `report.md`、`logcat.txt`、`crash.txt`、`screen.png`。它只读数，不改设备上的游戏和存档。

回报什么（`report.md` 里都有，整段贴进 Issue）：
1. 机型、芯片、系统版本、刷新率；
2. 程序号（不写游戏名）；
3. **未接清单**：新层遇到没接的命令不会停，按「类别 名字」记一笔、每种只打一行，一局列全——这张清单就是这台设备、这款游戏还缺什么；
4. 其它带【红】的日志行，去重计数；
5. 最后一行呈现读数（已呈现多少帧、丢多少帧、累计绘制多少笔、跳过多少笔）；
6. 画面情况：看本地的 `screen.png`，在 Issue 里用文字选（正确 / 全黑 / 缺东西 / 花屏 / 没出画面）。**截图不上传**；
7. 进程是否还在；崩了把 `crash.txt` 一起打包上传。

### B. 鸿蒙平台件
按三个头写鸿蒙的实现，把回放核心与 Vulkan 后端链进鸿蒙的构建：

| 头 | 入口 |
|---|---|
| `graphics/nvn/replay/nvn_plat.h`（版本 1） | 一行日志、调试开关、可写目录 |

安卓的对照实现在 `android/native/gfx_plat/`。回放核心与后端注释外不许出现平台头、不许直接读系统属性或环境变量，由 `make native-test-nvn_replay` 里的分层扫描守着。接口不够用就提 Issue 或直接在 PR 上说，接口头的版本号由维护方升。

PR 要附：一局 2D（0100633007D48000）的 `report.md`（同 A）。

### C. 回放核心 / Vulkan 后端里的代码任务：开放一部分
3D 那款已经进到游戏场景（11-11），分层和契约没有因此返工——一路补上的都是语义：内容从哪来（[对照_iOS回放层语义.md](对照_iOS回放层语义.md) 第 4 段）、校验层报出来的图像布局与附件视图（第 9 段）。外部普查（天玑 9000、骁龙 8 Elite）也已经把「别的游戏缺什么」列出来了，所以下面按「拦住出画面的」和「其它」两组开放。

**现在可以领的**（先开 Issue 写明领哪一项，一项一人；验收：回放核心的过 `make native-test-nvn_replay`，后端的过 `bash android/tests/vk/run.sh`，各带一条期望值手算的用例）：

*普查里拦住出画面的（最要紧）*
- **带几何 / 细分着色器的程序**（未接清单里的 `shader stages_0x7_not_vs_fs` / `stages_0x1f_not_vs_fs`）：四份普查里三款因为它一笔都画不出来。要动三层——平台件向编译器要多阶段程序（`android/native/gfx_plat/nvk_shader.c`）、后端的管线接多阶段、核心按阶段绑定。大项，先开 Issue 把方案对齐再动手
- 块压缩格式建图在不能直接采样的设备上走计算解码（#682 的 `BC format … needs compute decode`；仓库里有现成的解码器，后端用例 `android/tests/vk/t_bc_decode.c` 在测它，新后端的 `nvn_gpu_tex_create` 还没接）
- 还没接的命令：`OP_CLEAR_TEX`、`OP_COPY_T2B`（贴图读回缓冲）、`OP_WAIT_SYNC`
- 贴图数组长度没填进编译请求（#682 的 `request.program.textureArrayLength is missing`）
- Mali 上建贴图视图时崩（#686）：要有 Mali 设备的人把那次 `vkCreateImageView` 的参数抓出来

*其它*
- 间接绘制、多重绘制
- 间接派发、计算阶段的图像绑定
- 按着色器声明的类型取贴图视图（立方体当二维数组读、桥不了的用同类的零贴图；iOS `nvn_mtl.m` @6660–@6682，校验层 07752 / 06479 那两类）
- 块压缩格式的贴图当渲染目标（核心已有深度贴图的影子 `rp_pass.c shadow_attach`，照 iOS 的 `bcrt_attach` 扩到「一块当一个像素」）
- 点 / 线填充模式
- 段内 GPU 时间戳（按报告所在位置给时间）
- 绑定没变时复用描述符
- 读随包的每款参数（`game.tsv`）

*已经有人领了的*：颜色附件视图带通道映射时改建恒等的附件视图（#684）、贴图拷贝里的多重采样解析（#655 / #673）。

**先不开放、维护方自己做的**：贴图上传与初始内容、内存池镜像与写跟踪、GPU 写回游戏内存、通道的合并与省载入（`rp_pass.c`）、着色器缓存；贴图拷贝的镜像、整数格式之间换格式（要先在契约里定接口）。理由：前四处正是眼下提帧率在改的地方，一天里会动好几次，外部照现状写的代码容易白写；3D 进了场景之后这几处的对错已经能验了，帧率这一轮收住就放开。

**已经做完、不用再做的**：三维贴图多层上传、只写部分通道的清除、遮挡计数、条件渲染、计算派发（直接给组数的）、贴图到贴图的拷贝（同尺寸直接拷、带缩放 / 换格式的）、深度贴图经颜色视图当渲染目标。

## 规矩

- **契约头一次一人改**：`graphics/nvn/gfx/nvn/nvn_backend.h`（现在 v6）和两个平台接口头的改动统一经维护方。要加入口先开 Issue 说要什么、为什么，不要直接在 PR 里改头。
- **不按厂商分支**：后端只按能力查询的结果走，不读厂商号和设备号。
- **没接的不许静默**：核心里没接的命令、后端做不了的事，一律走 `nvn_unimpl(类别, 名字, 位置)` 记账，不空实现、不写假结果。
- 仓库里的文字（代码注释、文档、提交说明、Issue）用程序号，不写游戏名；不上传游戏文件、密钥、存档、游戏截图。
- 一个任务一个 PR；测试的期望值要能不跑被测实现就算出来。

## 怎么编出新层的包

工具与一次性准备同 [android/README.md](../android/README.md)「Which build path to use」：macOS（Apple 芯片）走宿主构建，Linux 走 docker。下面是 macOS 的命令。

要装的：Android SDK（platform 36、build-tools 36.0.0、NDK 29.0.14206865、CMake 3.31.6）、JDK 17、python3、git、curl；宿主还需 bash、tar 和 SHA 校验工具（`sha256sum` 或 `shasum`）。.NET 由准备脚本自己引导一份固定版本，Gradle 由仓库的 wrapper 获取，不用另装。

准备和构建缺省共用 `~/.cache/s2arm-build`：准备脚本会删除当前依赖身份的旧凭据，并在成功后只保留最近使用的 4 份身份凭据。如果这台机器还有别的构建在使用该缓存，可在仓库根目录先设一个专用目录，再在同一 shell 里执行下面所有步骤：

```bash
export S2A_BUILD_CACHE="$PWD/build/apk-cache"
```

如果此前单独设置过 `NUGET_PACKAGES`、`GRADLE_USER_HOME` 或 `ANDROID_USER_HOME`，也要将它们指向专用目录，才能隔离这些缓存。注意：准备脚本另外在 `$HOME/s2a-apk-host-prepare.*` 下建立临时源码及构建树，退出时自行清理；`S2A_BUILD_CACHE` 不改变临时树的位置，`$HOME` 也需要有足够空间。

```bash
# 一次性（要联网）：下固定版本的 .NET、NuGet / Gradle 依赖、编解码库与 OpenSSL 源码
bash android/host/prepare.sh

# 下面两步用同一组环境变量
export S2ARM_ANDROID_CS_SERVICES=static S2ARM_ANDROID_VK_ENGINE=1 S2ARM_ANDROID_VK_BACKEND=nvk

# 第一步（每棵工作树做一次）：全量构建，把 C# 服务层的静态库编进这棵树
bash android/host/build.sh

# 第二步：出能起游戏的调试包；以后改了图形层只重跑这一条
bash android/host/build.sh -Ps2arm.nativeMode=game :app:assembleDebug

# 产物
ls android/app/build/outputs/apk/debug/app-debug.apk
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

两步不能省成一步：直接跑第二步会停在 `Run cs/build.sh with S2ARM_ANDROID_CS_SERVICES=static first`——带了 Gradle 任务名的调用只跑 Gradle，不编服务层；准备脚本是在临时目录里编的，不会把服务层留在你的工作树里。

实测（11-11，Apple 芯片 Mac，全新克隆 + 全新缓存目录）：

| 步 | 用时 | 说明 |
|---|---|---|
| 准备 | 1280 秒 | 要联网；下载约 2.1 G（构建缓存 1.4 G + Gradle 0.7 G） |
| 全量构建 | 140 秒 | 依赖已由准备步下好（这一步断网能不能过没单独验证） |
| 游戏模式出包 | 22 秒 | 产物约 53 MB |

准备脚本末尾如果报「准备期间依赖清单变化；未写完成标记」：实测那一次它报了这一行、退出码非 0，但依赖已经下齐，后面两步照常成功。这个标记只给离线门禁用，不影响出包；为什么会报还没查清。

其它准备错误不能按这条处理。例如一次空缓存准备下载 Opus 时遇到 `curl: (35) LibreSSL SSL_connect: SSL_ERROR_SYSCALL`，准备未完成；检查网络后重跑准备才继续。

补充实测（11-12，Apple 芯片 Mac，提交 `857927e3`，工作树及构建缓存新建；该提交在当时 main 之上修正了重复的安卓中文资源）：JDK 17.0.21、Python 3.15.0、Git 2.54.0、curl 8.7.1；准备脚本引导 .NET 10.0.403 和 Gradle 9.8.1。首次准备下载失败（12 秒）；重跑 515 秒，构建和链接审计通过，但末尾仍报上述依赖清单变化、退出 1。随后全量构建 56 秒、游戏模式出包 13 秒，均退出 0，APK 为 52,813,362 字节。该记录只证明这次宿主构建；运行新层仍须按下文在设备日志确认。

| 变量 | 作用 |
|---|---|
| `S2ARM_ANDROID_VK_BACKEND=nvk` | 选新图形层；不设就是旧层 `nvn_vk` |
| `S2ARM_ANDROID_VK_ENGINE=1` | 把共用的图形前端编进包 |
| `S2ARM_ANDROID_CS_SERVICES=static` + `-Ps2arm.nativeMode=game` | 能起游戏的构建（服务层静态链进单库）；不带是只有外壳的诊断包 |

装好后怎么确认跑的是新层：起一局后日志（`adb logcat -s S2Arm`）里有一行 `nvk session: backend open on <显卡名>`。没有这一行就是包没带 `nvk` 编。

导入游戏：在应用里用自己的游戏文件和密钥导入（同现有安卓流程）；游戏文件和密钥不进仓库、不进 Issue。
