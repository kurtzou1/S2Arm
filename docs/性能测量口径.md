## 两种局

| 局 | 怎么起 | 读数能不能用 |

| **测量局**（缺省） | `tools/dev_run.sh` 不带重探针；起局环境自动带 `S2A_DEV_FACILITIES=0`（壳里开发设施按发布包口径关，等同 Info.plist `S2ADevFacilities=0`） | 帧率 / GPU 中位 / CPU 功率 / 整机功率都作读数 |

## 小效应用同局交替，不用分局对照（11-12）

量「开一个开关省不省 GPU / CPU 时间」时，效应在 1 ms 级就不要分局比：机身热起来后 GPU 降频，同一配置连跑两局，每帧 GPU 中位能差 4 ms、整机差 1 W 以上（11-12 实测：同包同开关两局 13.19 / 17.32 ms），局间波动把效应盖掉。

做法：被测开关做成按出图次数分段交替（偶数段关、奇数段开，例如每 120 次出图换一次），一局里采 200 秒左右，拿相邻的「关、开」两段凑一对：

- 每段丢掉首尾各 15 帧（切换瞬间与在途提交），取段内每帧 GPU 时间的中位数；
- 报成对差的中位数、均值，以及「开更低」的对数 / 总对数；
- 同时报两臂每帧绘制笔数的中位数：差得多说明自动玩家路线让场景对不上，这局不算；
- `frames.tsv` 第 n 行的 `gpu_us` 是第 n − 1 帧的，分段时按「帧号 − 1」算段号。

这样两臂在同一局、同一热状态、相邻场景里，局间波动成对抵消。11-12 一例：38 对，成对差中位 −0.65 ms（−4.1%），27 / 38 对开更低；而同一改动分局跑四局分不出方向。

整机功率、帧率这类大效应（差 1 W、差 10 帧以上）仍可分局比，但要写明每局的热状态，电量 100% 且不在充电（账本「充满」）才进定量。交替开关属于被测改动本身，不算重探针；带它的局写明「同局交替」。

## 报告写法

读数后面写局的口径：「测量局」或「诊断局（开了什么）」。跨口径不比；旧口径读数要引用就标「旧口径，可能偏低」。
