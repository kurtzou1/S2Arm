# Duo 通用上下分屏

关联任务：[#249](https://github.com/jhaizhou-ops/S2Arm/issues/249)。参考 nxnative 的 `touch-the-wild` 分支（`8188028655e625120e5291aa7d346532bb9238a9`）的系统铰链与区域处理方式，在现有虚拟手柄上增量实现。

## 玩家可见行为

分屏和方向是 App 级设置，所有游戏共用，在游戏内设置、游戏库设置和系统设置中使用相同的保存值。

| 设置 | 保存值 | 行为 |
|---|---|---|
| 上下分屏：自动 | `splitScreen=auto` | 仅系统报告半折叠时开启，竖屏本身不触发 |
| 上下分屏：开启 | `on` | 始终开启，横屏也保持上下分屏 |
| 上下分屏：关闭 | `off` | 始终关闭 |
| 屏幕方向：自动 | `screenOrientation=auto` | 分屏时申请竖屏，否则申请横屏 |
| 屏幕方向：横屏 | `landscape` | 申请横屏，与分屏开关独立 |
| 屏幕方向：竖屏 | `portrait` | 申请竖屏，与分屏开关独立 |

普通手机沿用相同规则：默认自动分屏 / 自动方向仍为横屏；手动竖屏并保持分屏自动或关闭时，游戏使用整块竖屏区域、按键叠加在画面上；手动开启分屏并使用自动方向时，同样申请竖屏并使用上区画面、下区按键。没有按机型取消手动选择。真实普通手机游戏的可玩性、按键体验仍待验证。

独立输入工作台已观察到：420 点宽的普通手机手动竖屏且不分屏时，沿用的普通默认布局中左右两对肩键重叠。本步修正的是分屏默认布局的肩键间距，普通竖屏不分屏的按键体验仍有上述限制。

两项缺省均为自动。系统拒绝方向请求或窗口允许自由调整大小时，按实际窗口布局。无法读取铰链状态时，自动分屏关闭，手动开启仍可用。新铰链接口用 SDK 条件编译和 iOS 27.1 运行期检查，不提高 iOS 18 的部署下限。

## 同一份区域

`ios/play_layout.*` 计算游戏目标区域、按键区域与折痕保留区域。横向折痕存在时按其上下边界切开，否则按窗口中线分屏；上下区分别扣除系统安全区。竖向折痕不取消分屏：游戏画面可能跨过折痕，按键避让其保留区域。

按键区域额外保留左右至少 16 点、底部至少 8 点。直连与通用出图层均读取同一游戏区域；直连触屏坐标直接读取实际出图图层矩形，通用路径在游戏区域内按真实出图比例换算。原有按键 / 仅触屏模式继续有效，下区不会作为游戏画面收到触屏点。

尺寸、方向、折痕或分屏变化时，释放触点、按键、摇杆与长按锁定状态；正在拖动编辑时放弃尚未保存的拖动。

## 下半区按键与存储

默认布局保留完整 16 键与左右浮动摇杆，同时兼容主线的固定摇杆、按键缩放与隐藏。主线新增的 2D 布局在普通和分屏位置各自可选，仍是 14 键、没有摇杆；在它上面编辑保存的自定义布局也保留 0 根摇杆，游戏库预览不画摇杆示意圈。分屏默认布局在下区重新排列：肩键位于上沿左右，减号 / 加号居中，十字键偏左内侧，ABXY 偏右；两侧保留浮动摇杆的启动空间。窄屏外肩键按安全区边界摆放后，内肩键至少隔开一个键宽和 8 点，间距与按键同时缩放，避免左右两对默认肩键相压。按钮尺寸随下区宽、高计算，分屏热区至少以 44 点为目标；重叠候选按距离选取。生产显示和命中先应用同一份按键缩放，再避让折痕；隐藏键不参与命中。

原生编辑沿用主线 B 菜单的整体卡片和贴键面板：整体卡片放在上区，单键面板放在下区选中键的另一侧；区域较矮时可滚动。编辑顶栏独立保留，窄屏分两行，完成与重置不会随面板滚走。齿轮仍是根视图的直接子视图，不放入下区裁剪层；编辑时沿用主线的暂时隐藏行为。本次已在主线 `b5318de7` 上重放，保留侧边浮动菜单、金手指、性能浮层、2D 八方向十字键、切换游戏动作、安装状态与进度缓存、最新主线本地化和存档转移的语言传递；分屏新增文案使用同一套原生与 Swift 字符串表。

布局仍用 F01 schema 1，按游戏保存：

- 普通布局保持原 `VPadLayouts/` 路径。
- 分屏几何、导入方案与选择记录放入 `VPadLayouts/split/`，不会覆盖普通位置。
- 主线新增的按键外观、固定摇杆模式 / 灵敏度与中心位置也随布局分别保存；普通布局已有设置保持原路径，切回时继续使用。
- 按键 / 仅触屏模式、手动选择标记、ZL / ZR 锁定开关共用原游戏设置；透明度、触感与摇杆手感仍为 App 级。

游戏库编辑页提供普通 / 分屏切换，可在横屏或竖屏编辑。`s2a_shell_vpad_preview` 由宿主返回区域和最终按键框，Swift 不重复计算分屏几何。更新后的 C 边界同步修改了宿主、桥接缺省实现、Swift 调用与测试。

## 宽屏目标

宽屏的目标比例来自上区可用区域的宽除以高。只扩展一边：3:2 上区对应 1920×1280，8:3 上区对应 2880×1080。沿用原来的能力名单、宽屏开关、原生比例选择和最大尺寸限制。

直连层另提供实际出图矩形，供第三步触屏映射使用。`S2APlayPublishSplit` 只发布已应用到窗口的分屏状态，由第三步窗口布局调用；纯几何计算和未应用的偏好不改变运行时状态。

装载尺寸或投影补丁时记录实际分屏状态。运行中的状态与装载时不同，才保持当前画布比例，日志提示重启；重复布局回调也继续保持，切回装载时的模式后恢复跟随屏幕。没有装载期补丁时仍允许跨模式热切。

不分屏的 Duo 合上、展开，以及分屏模式未改变时的尺寸变化，继续沿用主线的满屏热切策略。本步不重写已装载补丁的值，也不扩大保护到这些既有行为。

`make native-test-widen_ios_screen` 覆盖 24 条断言：固定尺寸补丁、仅投影补丁、普通合上展开、起局已分屏、重复回调、切回原模式恢复，以及无补丁仍可热切。新增的六项行为检查在原有宽泛保护下全部失败；修后 24/24 通过。恢复宽泛保护、移除分屏保护两个负对照各有 6 项失败。iOS 两处出图层另作 SDK 类型检查；这些合成检查不证明真实游戏画面。

不包含任何游戏专用的 UI 移动、硬编码游戏地址或游戏专用配置。

## 共享设置

两项已登记到 `launchers/shared/game_settings.v1.json`，id 为 `splitScreen` / `screenOrientation`，scope 为 `app`，仅在已实现的 iOS 平台展示。游戏内设置、系统设置和 Swift 游戏库均按这些 id 读写同一 App 的 `NSUserDefaults`，沿用主线 `padFace` 的存法；所有游戏共用，不另起存储文件。

旧 `S2ASplitScreen` / `S2AScreenOrientation` 只作为迁移来源：规范键不存在时迁入合法旧值，规范键已有值时优先保留；迁移后删除旧键。非法值回自动并清理，不从旧值重新恢复；未选择时只返回自动，不写入默认值。生产入口不对这两项调用 `registerDefaults`，默认值由读取逻辑返回。检查另确认持久选择优先于注册缺省。

本轮合成检查为区域 / 设置 39/39、分屏命中与几何 146/146、体感方向 11 组，Swift 宿主 12 项。修改前新的设置检查检出 11 项原生不符、Swift 迁移用例 16 个不符；负对照“旧值覆盖规范值”检出 6 项、“保留旧键”检出 5 项、Swift 停用迁移检出 2 个不符。系统设置的规范键、三组选项值与共享表逐项核对。默认分屏顶排新增 27 条检查，覆盖五种区域的六键逐邻间距与 388 点手机的左右手算间距；恢复原肩键比例位置有 4 项不符。

本次 `b5318de7` 变基后的 2D 接线补充检查：游戏库宿主 25/25，覆盖普通 / 分屏分别选择 2D、转屏后重算、切回默认、自定义保存与重开；错误地把所有内置方案退回默认的负对照有 5 项不符。2D 几何 28/28，覆盖八方向、中心死区、圆外与下区非零原点；主线 2D 的 14 键、0 根摇杆和导入 / 保存行为保持。Swift 宿主 17 项通过，含主线安装进度、蓝点与设置迁移检查。这些是合成检查，未操作本轮模拟器、未验证真实游戏的八方向按下 / 松开体验。

Mac 启动器继续按共享表的平台字段过滤展示；不能把登记这两个 iOS 项解释为 Mac 宿主已有分屏。

独立输入工作台 `ios/lab/` 复用生产窗口、设置和按键代码，可用于无游戏资源的界面验证。模拟器不提供真实铰链，不能替代 Duo 半折检测、游戏内触屏坐标、宽屏画面及真实组合操作验收。完整贡献者自检的本机缺项、实际执行结果与负对照随交付记录单列。
