# 排查手册：自动玩家没到 MARK / 没进可玩画面

适用范围：跑完一局（`runtime/run_mac.sh`、普查）以后 `host.log` 里没有 MARK 行，`ap_summary.json` 写 `"marked": false`，或者进局检查报「不过」。游戏崩了、出图停了，先看 [原生层 ② 进不去与 Break](原生层_进不去与Break.md)。

自动玩家 11-01 起是「AI 看屏驾驶」（`tests/autoplay/autoplay.c`）：每一步截一张图交给看图模型，模型回「按哪几个键」和「现在是不是已在游戏里操纵角色」；宿主读数确认进局。旧架构的摇杆探测、手录进局路线、离线重判工具都已删除，本手册只讲现行机制。门槛和日志格式抄自代码，代码改了以代码为准。几个词先说清：

- **MARK**：自动玩家认定「已在游戏场景里、可操控」的那一刻，`host.log` 打一行 `S2A 标记 MARK：帧 <N>`。帧率、能耗窗口从它起算。
- **进局双证**：模型说可操控 **且** 宿主读数到场景量级（每帧绘制数或渲染遍数明显高于开局基线），两条都满足才打 MARK。模型不单独判过。
- **驾驶员**：看图模型。缺省先问 Jev（`tests/autoplay/vision_jev.py`，选择题、约 2 秒），卡住时升级到对话模型（`tests/autoplay/vision_or.py`，OpenRouter；Spare-host 直连时走 kimi）。外发只有这一张截图和题面。
- **试过没用**：在某一页按了画面没变，或按了走回头路，这些键记进这一页的「试过没用」名单，下一问告诉模型别再答。
- **学路线**：每一局走过的有效步记进 `~/.s2arm/run/s2arm/ap_learn/<程序号>.tsv`，下一局先按页面摘要回放，对不上再交回模型。
- **局目录**：一局的输出目录（`S2A_AUTOPLAY_OUT`，Mac 局缺省就是局目录）。

结论先行：**先看 `ap_summary.json` 的 `why` 和 `vision/` 下最后几张截图**，分清是「停在菜单里没走到场景」「到了场景但读数不到」还是「局时不够」，再对症查。

## ① 症状长什么样

截图不进仓库，下面用日志字面和读数描述。

| 症状（`why` 或日志） | 意思 | 先去哪 |
|---|---|---|
| `导航卡住（步数上限 80 步）` | 问了 80 步还没进局，多半在几页之间打转 | ③ 1、③ 2 |
| `导航卡住（驾驶员连续 3 次没给出回答）` | 模型答了，但答案被「试过没用」整个滤空；或接口失败 | ③ 3 |
| `导航卡住（驾驶员连续 3 次没给出可用键）` | 模型答的键不在允许集合里（拼错、编造的键名） | ③ 3 |
| `导航卡住（导航 N 秒没进局，上限 300）` | 导航时长（扣掉等模型的时间）到了放弃线 | ③ 1 |
| `导航卡住（离收局只剩 N 秒，不再问驾驶员）` | 局时快到了，等模型太久把局时吃光 | ③ 4 |
| 「模型说可操控但读数未到场景量级」反复出现 | 模型认为进局了，宿主读数不认：低绘制场景或模型误判 | ③ 5 |
| 「模型说可操控却答了 + / -」 | 暂停页 / 过场被模型当成可操控，被拦下（正确行为） | ③ 6 |
| `导航卡住（没有视觉驾驶员，也没有学过的路线）` / `导航卡住（看屏驾驶员不可用：…）` | 本机没有 claude 命令行或没登录（`or` 后端：没有 OpenRouter 密钥）、也没学过这款 | ② 驾驶员在不在 |
| 出图停 60 秒 | 不是自动玩家的问题 | [原生层 ② 进不去与 Break](原生层_进不去与Break.md) |

## ② 用哪个工具、看哪几行

### 局目录里看什么

| 文件 | 内容 |
|---|---|
| `ap_summary.json` | `marked`、`mark_frame`、`why`、`stage`（停在哪个阶段）、`steps` / `vision_asks` / `vision_s`（问了几次、等模型共几秒）、`presses` / `presses_changed`、`replayed_steps`、`mark_delay_s` |
| `vision/v<序号>.png` | 每一问交给模型的截图，按序号就是导航的过程 |
| `vision/v<序号>.json` / `.json.log` / `.json.err` | 模型的回答、走了哪个后端、耗时、费用；`.err` 里有接口报错（如 HTTP 403） |
| `ap_stuck.png` | 没到 MARK 收局时的最后一张 |
| `ap_mark.png` / `ap_mid.png` / `ap_end.png` | 到 MARK 后的局内截图（五问「画面」格看它们） |

### host.log 里自动玩家的行

全部以「自动玩家：」开头，按时间顺序读就是导航过程：

- `导航 → 驾驶员 #<N>（截图 vision/v<N>.png，<秒> 秒，退出 <码>）→ 按键 [...]；可玩 是/否；说明：...`：一问一答。说明以「Jev 选」开头是快后端，否则是升级后端。
- `按 <键>（第 N 下；按住 X 秒）→ 画面变了 / 画面没变（帧 a → b，秒）`：这一键的效果。
- `<键> 第一次没反应，隔 2 秒再按一次`：页面刚出来不收键时的重按。
- `这页试过没用的键 ...`、`回到问过 N 次的页（第 K 页），这页试过没用：...`：「试过没用」名单的变化。
- `按 <键> 回到走过的第 K 页（走回头路）`：按了反而退回去。
- `按 <键> 又停在同一页（页内来回、没进展），记为试过没用`：同一组键第二次「画面变了却还在这页」就记进名单（单次变化不算，可能是光标挪了一格）。
- `<键> 按了没动，这组后面的键不按`：组合答案（如 `LEFT+A`）里方向键没挪动，后面的确认键不按（它们以挪动成功为前提）。
- `按 <键> 进了一页、再按 <键> 又回到原页：<键> 是开关` / `<键> 是开关…现在没开着，这次不按、等 N 秒`：只认 + / −（暂停类）。认成开关后没开着时不按、等画面自己走（10 秒起翻倍到 160 秒，不计步）；等的时候画面一直不动就翻转开关状态再按。
- `接上第二个手柄（驾驶员要单独按二号手柄：...）`：驾驶员答了 `2:<键>`，从此两个手柄各按各的。
- `实时通道读到 / 实时通道 REC:… / PASS:…`：`S2A_AP_LIVE` 文件里人追加的行；只认录帧与逐笔日志两种，导航不收。
- `学过的路线 ...，N 步，先回放`、`回放对不上（页相似 ...）`：学路线的使用情况。
- `开局基线 每帧绘制 a、渲染遍数 b（进局要 ...）`：进局读数门槛。
- `导航 → 局内段（依据：...）` 紧跟 `S2A 标记 MARK：帧 <N>`：进局成功。
- `自动玩家结论：到 MARK / 没到 MARK；...`：收尾一行，和 `ap_summary.json` 的 `why` 一致。

### 驾驶员在不在

- 后端由 `S2A_VISION_SH` 指的脚本决定，缺省 `tests/autoplay/vision.sh`；脚本里 `S2A_VISION_BACKEND` 缺省 `cli` = 本机 `claude` 命令行直连（用这台机器上 CLI 自己的登录），`or` = OpenRouter（钥匙只从仓库外 `~/.s2arm/.secrets/openrouter.key` 读），`jev` = 先问 Jev 再问 CLI。中转站档 11-12 起删除（中转站停用）。
- 后端不可用（PATH 上没有 `claude` / CLI 没登录 / `or` 没钥匙或回过 402）：起步或第一问就报【红】「看屏驾驶员不可用：<原因>」并收局，`ap_summary.json` 的 `why` 写同一句；不再当成「这一问没答」连问 3 次。学过这款路线的，不可用时仍可回放。
- `or` 后端（`vision_or.py`）顺序：OpenRouter 各模型（`S2A_VISION_OR_MODELS` 逗号分隔），一档失败落下一档，都失败退出 1；没钥匙 / 402 标记在 = 不可用、退出 3。
- 回过 HTTP 403 的档记在 `~/.cache/s2a/vision_or_403`（走代理的记 `_px`），一小时内跳过、过后自动作废；网络变了（如 Spare-host 开 VPN）不用人清。11-01 Spare-host 开 VPN 直连：sonnet 单问 3.1–3.6 秒、0 次 403。
- 单测用假驾驶员 `tests/autoplay/fake_vision.sh`，不联网。

### 普查与快检怎么判进局

五问的「画面 / 帧率 / 满屏 / 直连」格由 `tools/quality_check.py` 与 `tools/score_cells.py` 读局目录出，帧率窗口只统计 MARK 之后。普查缺省全能力（屏宽 2346、满屏开），局时按等模型的秒数顺延（`S2A_RUN_EXTEND_MAX`，上限缺省 300 秒）。

### 可调的开关（缺省值）

| 开关 | 缺省 | 作用 |
|---|---|---|
| `S2A_AP_MAX_STEPS` | 80 | 导航步数上限 |
| `S2A_AP_GIVEUP_S` | 300 | 导航放弃时长（扣掉等模型的时间） |
| `S2A_AP_VIS_LEFT_S` | 45 | 离收局不足这么多秒就不再问模型 |
| `S2A_AP_END_LEFT_S` | 20 | 离收局不足这么多秒直接收尾 |
| `S2A_AP_LEARN_DIR` | `~/.s2arm/run/s2arm/ap_learn` | 学路线目录；单测指到临时目录 |
| `S2A_JEV_FLOOR` | 0.3 | Jev 把握低于 0.6 但不低于它时照用，更低才升级 |
| `S2A_VISION_PROXY` | 空 | 只给 OpenRouter 档用的代理（Spare-host 上是 ssh 反向隧道出口）；连不上退回直连 |
| `S2A_VISION_BACKEND` | `cli` | 驾驶员后端：`cli` 本机 claude 命令行 / `or` OpenRouter / `jev` 先 Jev 再 CLI |
| `S2A_AP_LIVE` | 空 | 实时通道文件，人往里追加 `REC:<名>` / `PASS:<名>` |

## ③ 常见根因（现象 → 根因 → 怎么认出来 → 修在哪）

### 1. 在几页之间打转，步数或时长用完

- 现象：`vision/` 里同几张画面反复出现，日志一串「回到问过 N 次的页」「走回头路」。
- 常见根因：是 / 否确认框光标默认在「否」、存档页靠指针 / 点触选、标题页光标停在灰掉的选项上、动画背景让每一键都「画面变了」却原地不动。
- 怎么认：看最后几问的 `.json` 里模型的 `why`，它通常已经说出了画面是什么；对照「这页试过没用」名单看它为什么没换办法。
- 同一页里有子状态（改选 / 光标在不同行）：某键在一个子状态里没反应，回到另一个子状态时它要能再按。现行：判出「页内来回」时，试过没用只留来回拉黑的键，别的状态下记的「没反应」作废（11-01 怪猎崛起 Spare-host 语言页，单测 ㉖）。
- 修在哪：画面类型的通用规则写进 `tests/autoplay/nav_rules.txt`（只此一份，Jev 与升级后端题面都读它；`vision_jev.py` 另有选项说明）；按页判定的机制在 `tests/autoplay/autoplay.c` 的页表与 `tried_add`。不按款写死路线。

### 2. 页面刚出来不收键，或要点触

- 现象：按 A「画面没变」，隔 2 秒再按才变；或换遍按键都不动、画面写着「请点触」。
- 根因：确认框淡入期间游戏不收键；掌机档的指针页只认点触。
- 怎么认：日志里「第一次没反应，隔 2 秒再按一次」；`why` 提到手形指针 / 点触。
- 修在哪：重按在 `autoplay.c` 按键循环里；点触提示在 `vision.sh`（按键试过 3 个都没用时提示改答 `TOUCH:x,y`），点触坐标按截图里游戏画面的高换算成画布坐标（高 720）。

### 3. 驾驶员「没给出回答」

- 现象：`.json.log` 里「答案全是试过的键，追问一次」后「升级后端失败 rc=0」，但 `.json.log` 里能看到模型其实答了一串键。
- 根因：答案里的键都在这一页的「试过没用」名单里，被 `vision.sh` 滤空。另一种是 `.json.err` 里 HTTP 4xx / 超时，接口真失败。
- 怎么认：`.json.log` 最后一行就是模型原话；对照日志里这一页的「试过没用」。
- 修在哪：滤空规则在 `vision.sh` 解析段；名单怎么记在 `autoplay.c` `tried_add`。

### 4. 局时被等模型吃光

- 现象：`离收局只剩 N 秒` 收尾；`ap_summary.json` 的 `vision_s` 占局时大半。
- 根因：卡住的页上反复升级到慢后端（单问 4–35 秒），或 Spare-host 上每次升级先吃一次 403。
- 怎么认：数 `.json.log` 里「升级后端」行和 `.json.err` 里的 HTTP 403。
- 修在哪：升级时机在 `autoplay.c`（同页问过 ≥ 2 次、且这页上一问 Jev 答了没推进才升级；升级问过下一问回到 Jev，卡住页上两者交替）；后端顺序与 403 缓存在 `vision_or.py`。

### 5. 模型说可操控，读数不到

- 现象：「模型说可操控但读数未到场景量级」反复出现。
- 根因：游戏开局就在场景里（基线本身就是场景量级）、或低绘制 2D 场景、或模型把菜单误判成可操控。
- 怎么认：看「开局基线」那一行和说可操控那几问的截图。
- 修在哪：进局读数门槛在 `autoplay.c` `scene_level`；「模型连续 3 步说可操控、绘制不低于基线」那条兜底也在那里。

### 6. 暂停页 / 过场被当成可操控

- 现象：MARK 截图是压暗加 PAUSE 字样的暂停页，或是没有 HUD 的过场。
- 根因：模型把暂停页当成局内。
- 怎么认：「模型说可操控却答了 + / -」被拦下（正确）；或升级复核说「不是可操控场景」。
- 修在哪：`autoplay.c` `gate_playable`（说可操控却答系统键判否；Jev 可操控概率低于 0.8 要升级后端复核）；学过的进局页回放也要模型当场确认。

### 7. 两人模式 / 小块变化被当成「画面没变」

- 现象：双人游戏卡在「加入」页，按 A 日志说「画面没变」，换遍键也不动。
- 根因：要二号手柄单独按；或这一键只改了几张小卡片，整屏均差很小。
- 怎么认：截图上有第二个手柄的提示；日志里按键后帧在走、画面判没变。
- 修在哪：`2:<键>` 规则在 `vision.sh` 题面与 `autoplay.c` 按键解析；局部变化（≥ 3 格亮度差 ≥ 40、0.8 秒后复看还在）在 `autoplay.c` 画面放行段。

### 8. 过场里按 + / − 把游戏暂停

- 现象：过场时按了 +，进暂停页，再问模型又按 + 退出，来回打转。
- 根因：+ / − 是开关键，过场本该等。
- 怎么认：日志「是开关」那一行。
- 修在哪：`autoplay.c` 开关识别（只认 + / −）与等待退避。

### 9. 「试过没用」把模型的整组答案误滤

- 现象：模型答 `LEFT+A`，被当成「A 试过没用」滤掉。
- 根因：名单旧版按单键比。现在按整组动作比（按住秒数也算），可操控的答案从不滤。
- 修在哪：`autoplay.c` `tried_add`（多键记 `K1+K2`）；`vision.sh` 与 `vision_jev.py` 按整组比。

## ⑤ 踩过的坑

- **「没给出回答」不是模型没答**：先看 `.json.log` 末行，多半是答案被试过没用滤空。
- **动画背景的页**：每按一键整屏都在变，单看「画面变了」会以为在推进；要看是不是一直回到同一页。
- **单测的时序**：假宿主按帧推进、自动玩家按真实时间等待，两边别各算各的；gate-host 并发负载下出帧会慢很多。
- **学路线会把错误也学下来**：学过的进局页回放必须当场再确认；路线明显错了就把 `ap_learn/<程序号>.tsv` 删掉重学。
- **Spare-host 直连**：Anthropic 模型回 403，升级后端在 Spare-host 上实际走 kimi，单问 20 秒以上是常态。
