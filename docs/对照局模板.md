# 对照局模板

所有「改之前 / 改之后」「开 / 关」的对照（帧率、帧时、CPU、内存、游戏速度）都走这一套：**同一份即时存档起点 + 固定输入 + 按进度结束**。不用 AI 自动玩家走进场景，也不按墙钟截窗口。

为什么：AI 自动玩家每局走的路不一样，到达代表场景的时刻差几十秒到几分钟，有的局根本走不到；按墙钟截窗口，慢的那局窗口里游戏进度少。两局比的不是同一段游戏过程，读数差多半是场景差。

## 三步

### 1. 存起点（每款一次）

```sh
S2A_PRIVATE_TOOLS=<维护方工具目录> S2A_ROOTS=<产物根> \
  bash tools/ab_fixed.sh snap <款> <快照目录>
```

起点开着 60 帧存（`S2A_FPS60=1`）。自动玩家只在这一步用一次：进到可操控的游戏场景（MARK），画面稳 2 秒后原地存一份即时存档到 `<快照目录>`。看一眼局目录里的 `ap_mark.png`，确认它就是要比的场景。之后的对照局都从这份快照恢复，起点分毫不差。

存起点用已有进度的存档（不给 `S2A_SAVES` 时用起局脚本的缺省存档，通常是社区存档，开机直接进局）。别给空存档目录：游戏会从新开局起，开场动画很长，自动玩家常常过不去（实测一款空存档 900 秒没进局，社区存档一次进局）。

选起点时看一眼场景：画面大半是水面反光、烟雾、粒子这类每帧都在变的东西时，`speed` 的路线比对会找不到对应画面，判据判不出（实测一款海面场景，两局 81 张有效对比 0 张）。这时换一个陆地、建筑这类静止景物多的地方重存起点。

快照各局共用同一份；对照局带 `S2A_SNAP_SAVE_ROLLBACK=1`，局里写的存档不会留到下一局。

### 1b. 起点不合适时挪起点

社区存档只有一份、存档点又落在水面这类比不出路线的地方时，不靠自动玩家碰运气，用一段固定手柄输入从旧起点走到合适的地方，原地存新起点：

```sh
bash tools/ab_fixed.sh move <款> <旧快照目录> <padrec.tsv>@<起始帧> <新快照目录>
```

同一段输入会走两次，第二份存到 `<新快照目录>.check`。两次新起点的画面（快照里的 `a_last.png`）一致（`tools/ab_fixed_snapcmp.py`，缩图相关 ≥ 0.9），才说明输入是确定的、新起点可复现；不一致就退 1，新起点不能用。

新起点画面大半是火焰、水面、烟雾这类每帧都在变的东西时，即使两次走到同一处，相关也到不了 0.9（实测一款坠海开场游 40 秒仍在火海边，两次相关 0.60）：这时改输入走到静止景物多的地方再存。

### 2. 选固定输入

| 要比什么 | 用哪种输入 | 模式 |
|---|---|---|
| 游戏速度（开 60 帧会不会变快） | 推住左摇杆向前，按真实时间每 100 ms 存一张路线缩略图 | `speed` |
| 帧时、CPU、内存、GC | 一段录好的手柄输入，按上屏帧数逐行重放 | `perf` |

手柄录像（padrec）格式：每行 `上屏帧号 \t 按键位 \t 左x \t 左y \t 右x \t 右y \t 毫秒`，按键位低 16 位同自动玩家的键位，摇杆超过半程折成方向。来源二选一：

- iPhone / iPad：开发设施开着时（`S2A_DEV_FACILITIES=1`，只在开发包里），人玩时自动录进 `Documents/padrec`。先从第 1 步的起点快照恢复，再人玩一段，这样录下来的输入就是从起点开始的；起始帧填恢复后录到的第一行的帧号。
- 手写：几行就够，例如「第 0 帧推住左摇杆向上、第 600 帧松开」。

回放按 MARK 后的上屏帧数对齐，所以 A、B 两局喂的是同样多游戏帧里的同一段输入。

### 3. 跑对照

```sh
# 游戏速度：同起点两局，都按 60 帧开恢复，原帧率那局录之前在局内切回原帧率
bash tools/ab_fixed.sh speed <款> <快照目录>

# 性能 / 内存：A B B A 交替（发热敏感的读数前后抵消），每组 2 局
bash tools/ab_fixed.sh perf <款> <快照目录> <padrec.tsv>@<起始帧> 'S2A_X=0' 'S2A_X=1' 2
```

- `speed` 为什么不「关着存、开着恢复」：游戏开局时按补丁算好的帧率、交换间隔留在快照内存里，开着恢复只改了补丁槽，游戏不会再算一遍（实测一款关存开恢复 300 秒仍 30 帧，冷起开 60 帧是 59.9）。所以两局都按存时的设置恢复，原帧率那局录之前走玩家在设置页关 60 帧的同一条路径切回去（`S2A_AP_ROUTE_HOLD=1`），等 5 秒再录。
- `speed` 判据 `tools/route_speed.py`：取原帧率局推杆后 t 秒那张图，在 60 帧局里找最像的一张、记它的时刻 t'，速度比 r = t / t'。按真实时间推进的游戏 r ≈ 1（绿），按帧推进的游戏 r ≈ 帧率比（红）。退出码 0 绿、1 红、2 判不出（帧率比 < 1.3，或两局没走同一条路线）。
- `perf` 判据 `tools/ab_fixed_perf.py`：只取宿主日志里「对照局：固定输入回放段 帧 a–b」这段帧，从逐帧表 `frames.tsv` 算帧间隔 p50 / p95 / 最大、GPU 均值、每帧分配、GC 停顿，从 `power up to frame` 行取每帧 CPU 能耗，从 `[S2A 内存]` 行取进程足迹峰值。每项给两组中位、B ÷ A、各组最小–最大；B 的范围与 A 的范围不重叠才算「超出同组波动」。两组回放段帧数差超过 1% 时不判（输入没放成同一段）。

任一局没到 MARK 或回放没放成，脚本退出 3，不拿半截局出结论。

## 局怎么结束

对照局喂完固定输入就收局：`speed` 录完路线、`perf` 放完手柄录像，自动玩家记下段落帧号后结束这一局。`S2A_LOOP_SEC`（缺省 1800 秒）只是兜底，正常不会碰到。

## 帧率补丁局中才生效的款

有的帧率补丁要游戏先测到一次慢帧才生效，开局后什么时候升到 60 帧不确定（实测一款开放世界游戏三局分别在 85、127、218 秒）。`speed` 模式的 60 帧局缺省先等标称帧率到 60（`S2A_AP_ROUTE_WAIT60`，缺省最多 300 秒），等了多久、到没到都写进日志；没等到照录，判据按录像期间的实际出图帧率算帧率比。

## 用在 iPhone / iPad 上

同一组环境变量（`S2A_SNAP_RESTORE`、`S2A_SNAP_SAVE_ROLLBACK`、`S2A_AP_PADREC` 或 `S2A_AP_SPEED=route` + `S2A_AP_ROUTE_OUT`）随起局环境传给真机即可，自动玩家走同一条对照局分支。真机局目录取回本机后，`tools/ab_fixed_perf.py --a … --b …` 照样判。

## 相关文件

- `tests/autoplay/autoplay.c`：对照局分支（即时存档恢复局不走导航，MARK 后喂固定输入、喂完收局）、`route_record`、`route_snap_save`、`padrec_play`
- `tools/ab_fixed.sh`：三种模式的入口
- `tools/route_speed.py`、`tests/route_speed_test.sh`：速度判据与单测
- `tools/ab_fixed_perf.py`、`tests/ab_fixed_perf_test.sh`：性能 / 内存读数与单测
