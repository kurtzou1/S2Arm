# 游戏缺陷修补表

`<main 构建号前 16 位>.tsv`：游戏自己代码里的缺陷、宿主调度挡不住的，出包时由 C 改写器按构建号精确改字（`runtime/rewriter/rewriter.c` `fix_rows`，环境变量 `S2A_FIX_TSV`）。

- 行格式同帧率表 c 行，收两种：
  - `c <模块> <偏移> word <原字> <新字>    # 理由`：原位换一条指令（偏移、字都是十六进制；字是小端 32 位指令字），分析前改。
  - `c <模块> <偏移> veneer <原字> <体字…>    # 理由`：原位改成 B 跳板，体字与记号（`adrp:x<n>` 取本模块键页、`bl:<偏移>` 调本模块函数）同帧率表 veneer，跳板末尾自动回到下一条；在生成之后改。用来给游戏自己无锁的并发调用包一把客体锁：锁字是本模块键页前 0x10 处（映像结尾可写空余的最后 16 字节，`pack/cpatch.py` `FIX_LOCK_TAIL` 不分给 FPSLocker 变量），体字 `adrp:x16` 后接 `sub x16, x16, #0x10` 取到。
- 原字不符（不是这一版）或点不在代码段：记改写缺口、不改。
- 与 `runtime/fps/` 分开：帧率表存在本身表示「本款已有我方帧率表」（社区帧率补丁不收），修补表不带这层含义。以后与按款旋钮表合并时按同一格式并入。
- 每条写清依据：崩溃现场、竞争过程、为什么改成这样不丢功能。
