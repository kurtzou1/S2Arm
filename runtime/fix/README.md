# 游戏缺陷修补表

`<main 构建号前 16 位>.tsv`：游戏自己代码里的缺陷、宿主调度挡不住的，出包时由 C 改写器按构建号精确改字（`runtime/rewriter/rewriter.c` `fix_rows`，环境变量 `S2A_FIX_TSV`）。

- 行格式同帧率表 c 行，收两种：
  - `c <模块> <偏移> word <原字> <新字>    # 理由`：原位换一条指令（偏移、字都是十六进制；字是小端 32 位指令字），分析前改。
  - `c <模块> <偏移> veneer <原字> <体字…>    # 理由`：原位改成 B 跳板，体字与记号（`adrp:x<n>` 取本模块键页、`bl:<偏移>` 调本模块函数）同帧率表 veneer，跳板末尾自动回到下一条；在生成之后改。用来给游戏自己无锁的并发调用包一把客体锁：锁字是本模块键页前 0x10 处（映像结尾可写空余的最后 16 字节，`pack/cpatch.py` `FIX_LOCK_TAIL` 不分给 FPSLocker 变量），体字 `adrp:x16` 后接 `sub x16, x16, #0x10` 取到。
- 原字不符（不是这一版）或点不在代码段：记改写缺口、不改。
- 与 `runtime/fps/` 分开：帧率表存在本身表示「本款已有我方帧率表」（社区帧率补丁不收），修补表不带这层含义。以后与按款旋钮表合并时按同一格式并入。
- 每条写清依据：崩溃现场、竞争过程、为什么改成这样不丢功能。

## 按函数指纹跨版本：`match/<程序号>.tsv`

精确表只对一个构建号生效。`runtime/fix/match/<程序号>.tsv`、`runtime/fps/match/<程序号>.tsv` 记「改哪个函数的第几个字」，出包时
`pack/fn_match.py tables` 在这一版 main 里按函数指纹找到同一个函数，展开成精确行交改写器（改写器不改）。格式、指纹取法见 `pack/fn_match.py` 文件头。

- 本构建号有精确表就用精确表，同类规则不展开。
- 一条规则在本版必须恰好命中一个函数：0 个 = 不适用（黄）；≥2 个 = 不唯一，整组不打（红）；定位后原字有一处不符 = 整组不打（红）。一组里全有全无。
- 修补表（缺陷修补）只在组里 `checked` 列出的构建号上打；别的构建号命中只报不打，人核过再把构建号加进 `checked`。帧率 / 步长表命中即打（速度比有判据可验）。
- 从精确表生成规则：`python3 pack/fn_match.py derive runtime/fix/<bid16>.tsv <该版 exefs/main> --out runtime/fix/match/<程序号>.tsv`，
  生成时自核：规则在原版本上展开必须与精确表逐字一致，不一致不输出。带 w 行（数据段地址）的表不支持，留在精确表。
